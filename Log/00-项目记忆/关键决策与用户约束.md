# 关键决策与用户约束

这些约束来自此前的执行过程和用户明确要求。后续 Agent 在修改工程前应先检查本文件。

## 用户明确要求

1. `.workbuddy` 不要删除，也不要擅自修改。
2. 需要删除文件时，移动到 Windows 回收站即可，不做永久删除。
3. 分析、执行计划、证据和交接文档优先输出到 `F:\WhisperSubtitle\Log`。
4. 架构工作应分批执行，由用户按顺序提示开始。
5. 没有明确要求时，不自动提交 Git。
6. 没有明确要求时，不自动 push、tag 或发布。
7. 用户希望更换新的 GUI/桌面架构，目标不仅是升级 Qt，还包括网页 UI 技术、交互感和审美。

## 已确认的工程决策

- 当前模块化重构基线保留为可回退的稳定版本。
- Python 转录核心有价值，应复用，不应为了新 UI 重写推理算法。
- 下一代 UI 首选 Web 技术，而不是继续深度美化 PyQt5。
- 下一代桌面架构首选 Tauri 2 + React/TypeScript + Python Worker。
- Tauri/Rust 层保持轻量，只承担桌面生命周期、系统能力、权限和 Worker 管理。
- Python Worker 负责模型、CUDA、转录、后处理和输出。
- React 前端负责视图、动画、任务状态、主题、图表和交互。
- 正式桌面 IPC 优先使用受控的 stdin/stdout JSON-RPC，不优先开放本地 HTTP 端口。
- PyQt5 在新 UI 达成功能等价和真实验收前保留为回退入口；用户已明确执行批次 7，表现层与专属测试已送入回收站，Python CLI 继续保留。

## “网页 UI 技术效果”的准确含义

用户需要的是使用 HTML、CSS、TypeScript、React 和动画/组件生态实现桌面界面效果，不是采用“WebUI 产品架构”。最终产品仍必须是本地 Windows 桌面应用：

- 用户双击桌面 EXE，在独立 Tauri 窗口内使用。
- React 页面只渲染在 Tauri 内嵌 WebView2 中。
- 不打开外部浏览器，不要求用户访问 URL。
- 不以 Gradio、Streamlit、NiceGUI 或浏览器管理页作为正式界面。
- 不默认启动 FastAPI、localhost HTTP 服务或 WebSocket 服务。
- Tauri 与 Python Worker 通过受控桌面 IPC 通信。
- 模型、媒体、输出、设置和 GPU 推理继续在本机离线运行。
- 网络能力只能作为明确选择的更新或下载功能，不能成为应用运行前提。

后续文档和实现统一使用“WebView 桌面界面”“Web 技术桌面表现层”或“React/TypeScript 桌面表现层”，避免简称为“WebUI”。

## 仍需用户确认的事项

- 新 UI 的具体视觉风格、品牌色、字体和布局方向。
- 是否只支持 Windows，还是未来考虑 macOS/Linux。
- 是否接受安装 Rust、Node.js/pnpm 和 WebView2 构建工具链。
- Python Worker 最终采用 PyInstaller onedir、嵌入式 Python 还是独立运行时包。
- 模型和 CUDA 运行时是由安装器管理，还是继续由用户手动放置。
- 是否需要自动更新、任务历史、字幕编辑、波形时间轴和多格式导出。
- 新架构是否继续使用 `master`，或创建 `codex/...` 迁移分支。

## 变更保护规则

- 涉及推理参数、后处理、文件命名或输出内容的变更必须明确说明，并更新对应 golden。
- 涉及依赖删除时，必须在全新隔离环境验证；复制旧虚拟环境不能作为证据。
- 涉及 CUDA 或打包时，必须做真实 NVIDIA GPU 回归。
- `Log/90-原始需求/` 中的历史需求原文不重写。
- 历史执行证据不因目录整理而删除。
- 新架构文档必须区分 `Accepted/Proposed/Implemented/Deprecated` 状态。
