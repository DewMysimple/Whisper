# 批次 2 执行报告：统一数据契约与 Preset 注册表

## 结论

批次 2 已完成。项目新增稳定的类型化数据契约，并将 preset 的 ID、CLI 别名、模块入口、显示信息、参数与后处理策略收敛到唯一 typed registry。CLI、GUI、四个兼容 Core 和 benchmark 均已改为读取同一数据源，旧入口、旧 preset ID 和 QSettings 恢复保持兼容。

未执行 Git 暂存、提交、标签或推送。

## 类型化数据契约

新增 `whisper_subtitle.domain.contracts`：

- `Preset`：冻结完整 preset 定义与嵌套参数，脚本名由模块入口派生。
- `TranscriptionRequest`：规范输入路径、canonical preset ID、可选输出目录与桌面保存选项。
- `TranscriptionResult`：关联请求、成功状态、输出路径和失败信息。
- `ProgressEvent`：传输无关的阶段、消息、进度计数与输入上下文。
- `BatchResult`：保留逐文件结果并提供成功数、失败数和退出码。

请求、结果、进度和批次契约将在批次 6 的统一应用服务中接入四条转录流程；本批不提前改变旧 Core 函数签名。

## 唯一 Preset Registry

`whisper_subtitle.domain.presets` 现在是唯一数据源，包含：

- canonical ID：`cn`、`cn2`、`en_v1`、`en_v2`；
- CLI alias：`cn`、`cn2`、`en`、`en2`；
- Core 模块入口与派生脚本名；
- GUI 标签、说明和分组；
- 完整 Whisper 参数；
- 后处理策略 ID 与显示文本。

模块导入时会验证：

- preset ID 唯一；
- CLI alias 唯一；
- Core 模块可定位；
- 后处理策略存在；
- 所有必需参数及 VAD 嵌套参数类型正确。

生产与测试工具中的手写 `PRESET_IDS` 或字面量 `PRESET_MODULES = {...}` 审计结果为 0。

## 兼容迁移

### Core

`core/presets.py` 已缩减为从 typed registry 派生的兼容字典视图：

- 四个旧 Core 仍可使用 `get_preset(id)["params"]`；
- `PRESETS` 仍为旧字典列表；
- `DISPLAY_KEYS` 仍为 list；
- `get_display_value()` 仍支持调用方传入同形自定义字典；
- 未移动或合并任何转录、后处理和文件输出逻辑。

### CLI

- `--preset` choices 和默认值来自 registry。
- 模块导入通过 CLI alias resolver 获取。
- `PRESET_MODULES` 名称为兼容保留，但已变为 registry 派生的只读视图，不再维护第二套数据。

### GUI 与 QSettings

- GUI 直接持有与 registry 相同的 typed `Preset` 对象。
- 模式按钮、说明、参数表、脚本检查与模块启动均读取 typed 属性。
- QSettings 原值 `en_v1/en_v2` 可继续恢复。
- 若曾保存 `en/en2` CLI alias，也会规范化为 canonical ID。
- 未知或已移除值回退 `en_v1`；保存时仍写 canonical ID。

### Benchmark

- 已删除 benchmark 中的手写 alias→ID 映射。
- 新增候选结果输出参数，验证批次不会覆盖正式 baseline。
- runner 会快照并在成功或失败后原样恢复 Core 自动生成的输入旁 Text 备份，避免污染已跟踪回归数据。
