# 新架构批次 1 执行报告

状态：`Complete / Accepted`。

执行日期：2026-07-15。

## 1. 批次目标

把下一代桌面进程通信从展示文案中分离出来，建立版本化、机器可读、跨语言可验证的 Desktop IPC v1 契约，同时保持现有 CLI/JSONL/PyQt5 行为不变。

## 2. 实现内容

### 跨语言 schema

- 新增 `contracts/desktop_ipc/v1/desktop_ipc.schema.json`，采用 JSON Schema Draft 2020-12。
- 每条消息固定 `schema_version: 1`。
- 定义 `command`、`event`、`error` 三种互斥 envelope。
- 拒绝未知字段，避免静默协议漂移。
- 新增协议索引、示例、生命周期和兼容规则说明。

### 稳定代码

Commands：

- `system.health`
- `system.environment`
- `model.load`
- `model.unload`
- `transcription.start`
- `transcription.cancel`
- `worker.shutdown`

Events：

### Python 协议层

- 新增 `whisper_subtitle.protocol`，不依赖 PyQt5、faster-whisper、Worker 或具体传输。
- 新增冻结的 `CommandMessage`、`EventMessage`、`ErrorMessage`。
- 新增一行 JSON 编码、严格解析、稳定错误映射和任务事件序列校验。
- command params 支持批次 0 已验收的结构化 `InputSource[]`、四 preset 派生 overrides、兼容/自定义 TXT/Markdown 输出策略。
- 参数 overrides 仅允许验收白名单和安全范围。
- `message` 是可选展示字段；状态由 method/event/code 和 data 决定。

### 任务生命周期

```text
task.queued
  -> task.progress*
  -> task.completed | task.failed | task.cancelled
```

序列必须使用同一个 `task_id`，必须从 queued 开始并以唯一 terminal event 结束。

## 3. 兼容性
