- `F:\WhisperSubtitle` 当前代码、协议和测试是功能事实来源。

## 以后如何启动一次 UI 回迁

用户给出类似以下明确指令，即视为授权执行一次新的第四阶段 UI 修改：

> 我已经在第三阶段工程再一次修改了 UI，你需要严格依据第三阶段工程的代码更新软件的 UI。

默认执行模型：

- 一次用户授权对应一次完整 UI 修改，默认不拆成多个外部批次。
- 单次修改内部由 Agent 自行设置代码冻结、结构审计、CSS 审计、正式状态映射、测试、Tauri 构建和日志封版等检查点。
- 内部检查点不要求用户重复授权。
- 如果只靠一个批次会显著增加功能契约、工作区覆盖或无法可靠验收的风险，Agent 必须在实施前说明原因并建议分批，由用户决定。
- 页面数量多本身不是拆批理由；只有存在具体、可说明的风险时才建议拆分。

该授权允许在 `F:\WhisperSubtitle` 内修改本轮 UI 相关代码、测试和第四阶段日志，并执行本地测试、Tauri 构建和启动烟测。它通常不授权修改第三阶段工程；只有用户像第 3 次修改一样明确要求“以正式软件 UI 为基准反向抽离”时，才允许在同一轮同步 `WhisperUI`。任何授权都不自动包含 Python/IPC/Preset/输出契约或 Git 暂存、提交、分支、推送和发布。
