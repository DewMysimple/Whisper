# 功能测试 001：SRT 字幕声画同步与单行排版

日期：2026-07-19。  
状态：已完成代码整改、自动化验证、真实 CUDA 媒体验收和正式产物替换；等待用户继续用完整媒体主观验收。

## 1. 分类澄清

本次不是程序报错，也不判定“中文防幻觉”功能发生错误。

用户反馈的核心是字幕声画同步：

- 有时声音尚未出现，字幕已经显示；
- 有时声音已经结束，字幕仍然显示；
- 部分连续字幕因为错误的时间分配开始累积偏移；
- 某些应按真实语音短句拆分的内容被按字符比例机械拆分。

因此本次归入“功能测试”，不写入 `报错处理日志`。

## 2. 人工测试资料

用户提供：

- `C:\Users\Administrator\Desktop\Whisper_Utilization\中文防幻觉_转录场景（我有批注哪里是不好的 问题比较大的）.txt`

第一份使用 `==...==` 标记字幕过早、过晚、结束延长、提前结束、句组不合理和后续累计错位。第二份给出用户按画面和声音人工校准的期待文本与时间范围。

期待文件中的第 8–10 条时间早于第 3–7 条，属于人工补写顺序；正式 SRT 必须按时间升序重新排序并连续编号，不能原样产生逆序 SRT。

## 3. 已确认的代码事实

当前四个正式 Preset 的 `word_timestamps` 均为 `False`。旧 SRT 流程只取得整段起止时间，再按字符权重把整段时间分配给子字幕。该算法无法知道每个词何时真正开始和结束，也无法表达不均匀语速与句间停顿。

同一原始课程前 32 秒使用 faster-whisper `large-v3-turbo`、CUDA、float16、中文防幻觉参数并仅在诊断调用中启用 `word_timestamps=True` 后，模型返回的词级时间与用户人工期待明显接近。例如：

| 内容 | 模型词级时间 | 用户期待 |
| --- | --- | --- |
| 咱们中国人在学校里学英语 | 0.620–2.460 | 0.900–2.700 |
| 问题是…教学的时候 | 5.320–7.820 | 5.366–8.066 |
| 根本不告诉你…什么音标 | 7.820–10.740 | 8.200–10.966 |
| 国际音标…Phonetic Alphabet | 21.880–24.820 | 22.066–25.266 |
| 简称 IPA | 25.260–26.360 | 25.500–26.700 |

这说明整改重点应为 SRT 专用的词级时间轴，而不是修改防幻觉阈值或重复清理语义。

## 4. 用户新增排版规则

SRT 排版默认参数 `max_lines_per_cue` 改为 `1`，即默认每条字幕最多一行。

`max_characters_per_line` 仍是独立可调参数。当一句内容无法同时满足单行行数、单行字符数和语义完整时，正式结果必须按时间顺序拆成多条单行字幕；不能为了把长句强塞进一条字幕而静默突破用户设置。

## 6. 实际代码整改

### 6.1 SRT 专用词级时间轴

`src/whisper_subtitle/application/transcribe.py` 只在输出计划包含 SRT 时，把本次执行参数副本中的 `word_timestamps` 设为 `True`。四个正式 Preset 定义中的 `word_timestamps=False` 仍保持不变，纯 TXT/Markdown 请求仍使用原参数。

`src/whisper_subtitle/domain/subtitles.py` 新增词级字幕路径：

- 读取 faster-whisper 每个 word 的真实 `start`、`end` 和文本；
- 合并 `In` + `tern` + `ational`、`Ph` + `on` + `etic` 等英文子词片段，避免错误拆词；
- 优先在强标点、有效逗号、模型 segment 边界和字符容量附近断句；
- 每条时间直接取第一个词开始和最后一个词结束，不再按整句字符比例分摊；
- 处理相邻时间边界时不把下一条字幕延后到真实发声之后；
- 如果测试引擎或旧引擎没有 word 数据，安全回退到原来的真实 segment 时间路径，不丢失输出。

防幻觉版仍只负责原来的内部重复与连续重复清理。本次声画同步整改不把“时间轴问题”误归因于防幻觉功能。

### 6.2 默认单行与旧设置迁移

- Python `SubtitleOptions` 默认 `max_lines_per_cue`：`2 -> 1`；
- React 四个 SRT 预设默认 `max_lines_per_cue`：`2 -> 1`；
- UI 摘要同步显示单行；
- 旧版持久化状态如果只是保存了历史默认值 `2`、并没有用户 override，则自动迁移为 `1`；
- 如果用户以前明确把该字段自定义为 `2`，仍保留用户值，不强制覆盖；
- Desktop IPC v1 仍允许用户在 `1–3` 行范围内自定义，协议范围没有收窄。

测试媒体来自用户标注对应原视频的前 32 秒，模型为 `large-v3-turbo`，运行设备为 `NVIDIA GeForce RTX 5070 Ti`，计算方式为 CUDA / float16，Preset 为 `cn2`。

32 秒样本最终得到 14 条 SRT：全部只有一行、每行不超过默认 18 字符、编号与时间严格升序。英文 `International Phonetic Alphabet` 因单行 18 字符限制被拆成相邻字幕，这是遵守用户当前参数，不是文字丢失；提高“每行最多字符”后可减少这类拆分。

模型第一词边界为 0.560 秒，而用户人工期待约为 0.900 秒。正式实现采用模型真实词级边界，不写入只适用于这一段视频的固定 0.34 秒偏移。后续如果完整媒体仍存在稳定、可重复的系统性偏移，应另开功能测试，使用多段样本统计后再决定是否增加全局字幕校准参数。
