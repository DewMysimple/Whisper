# 第 10 次修改：文件输出区重构与默认路径恢复

执行日期：2026-07-19。  
状态：正式 React UI、输出路径状态修复、组件测试、E2E、Tauri Release 构建和桌面烟测均已完成；等待用户目视验收。

## 1. 用户反馈与授权范围

用户指出转录工作台“文件输出”区域存在三类问题：UI 设计较差、功能层级混乱、部分字体与文字拥挤；选择自定义路径后无法直观恢复默认状态。

本次是正式软件第 10 次 UI/功能修改，仅修改 `F:\WhisperSubtitle`。没有同步或修改第三阶段 `C:\Users\Administrator\Desktop\WhisperUI`。

## 2. 根因

旧实现不只是视觉问题：`setOutput()` 会把任何格式或冲突策略变更都自动转换为 `custom` 模式。因此，仅勾选 Markdown 也会让状态变成“自定义输出”，随后又因为没有自定义根目录而要求用户选择路径。路径模式、文件格式和冲突策略被错误耦合。

旧“恢复兼容输出规则”位于卡片底部，视觉权重很低，而且一次恢复会同时重置路径、格式与冲突策略，无法表达用户真正需要的“只恢复默认位置”。长 Windows 路径与“更改”动作也被塞进同一横行，在内容字号增加后发生明显拥挤和截断。

## 3. 新的信息结构

输出区标题从含义模糊的“输出策略”调整为“文件输出”，内部固定分为三层：

1. **输出位置**：显示“跟随每个媒体文件”或“自选输出文件夹”。
2. **生成文件**：TXT、Markdown 或 SRT 各自独立成行。
3. **同名文件**：单独展示冲突处理策略。

位置状态使用“跟随媒体 / 自选目录”，不再向用户暴露含义不清楚的“兼容模式 / 自定义模式”术语。

## 4. 路径交互修复

- 默认位置明确说明：在每个媒体文件旁自动创建当前启用格式对应的 `Text`、`Markdown` 或 `SRT` 子目录。
- “选择输出文件夹”是默认状态下唯一的位置操作。
- 选择路径后，完整 Windows 路径进入独立代码文本区并允许换行，不再与标题和动作挤在一行。
- 自定义状态提供同等权重的“更换文件夹”和“恢复默认位置”。
- “恢复默认位置”只把 `mode` 恢复为 `compatibility` 并清空 `rootDirectory`；TXT/Markdown/SRT 选择和同名策略保持不变。
- 格式复选框和同名策略不再隐式修改路径模式。
- 当所有格式暂时关闭时，位置说明显示“尚未选择输出格式”，避免出现空目录名称句子；启动任务仍沿用既有“至少一种格式”校验。

## 5. 视觉与可读性

- TXT 和 Markdown 从拥挤的两列卡片改为纵向独立行，扩展字号后仍有稳定空间。
- 格式缩写、名称、用途和开关各占一个明确列；不再出现“纯文本 TXTText 子目录”式文字粘连。
- 自定义路径允许任意 Windows 长路径换行。
- 路径动作在常规卡片宽度中双列排列，520px 以下自动改为单列。
- 输出位置、格式、同名策略都有独立标题与辅助说明，减少无意义留白并提高扫描效率。
- 视觉继续使用正式工程 R02 Token；本次设计签名是“目的地卡片”，强调媒体文件到输出子目录的真实关系，没有引入第三阶段静态演示。
