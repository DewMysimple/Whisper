## 3. 模型与任务语义

- 空闲选择已安装模型时调用真实 `model.load`，使用独立 180 秒超时；
- 有运行或排队任务时只更新后续新任务默认值，不替换正在使用的模型；
- `TranscriptionDraft`、持久化任务快照和 Worker 任务实体都冻结 `modelId`；
- Worker 在队列边界按每个任务快照加载对应模型，运行中和已排队任务不受后续选择变化影响；
- 历史任务重试沿用原任务模型，启动前重新扫描本地模型；模型已缺失时阻止重试并引导到模型工作台；
- 任务列表、详情和重试确认框显示真实模型名称；
- 旧配置、旧任务及旧客户端未提供模型字段时统一兼容为 `large-v3-turbo`；配置 `schemaVersion` 继续为 1；
- 空闲预加载失败时恢复原默认选择，并尝试恢复先前模型；恢复也失败才显示 Worker 未加载及真实错误；
- Worker 的 `system.health` 每 5 秒只校正当前加载状态，不增加性能轮询日志噪声。

Desktop IPC v1 仅按本次明确授权做向后兼容扩展：`transcription.start.params.model_id` 和 `task.queued.data.model_id` 均为可选字段；旧客户端省略时仍使用 turbo。既有命令、事件、错误和任务生命周期没有改变。

## 4. 本地模型发现与运行时

- Python 与 Rust 共同采用六个固定模型 ID，不接受任意网络仓库或外部路径注册；
- 模型目录必须同时包含 `config.json` 和 `model.bin` 才视为完整；
- `large-v3` 与 `large-v3-turbo` 使用精确目录/仓库名，避免子串误命中；
- turbo 兼容当前 Mobius 缓存和旧 Systran 缓存，但两者都是完整精确仓库名，不做模糊查找；
- 环境检查由“必须存在 turbo”调整为“六个支持模型至少存在一个完整模型”；具体任务选择缺失模型时仍拒绝启动；
- 正式 Host 始终向 Worker 传递统一模型根目录，当前正式 turbo 模型无需搬移；
- 第一版没有下载、导入、注册或删除模型，也没有联网路径。
