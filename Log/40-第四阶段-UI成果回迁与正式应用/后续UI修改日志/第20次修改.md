## 3. 同名文件执行前确认

- 前端输出策略现为“执行前确认覆盖同名文件”和“自动安全重命名”；旧 `fail` 配置在 schemaVersion 1 内迁移为 `confirm_overwrite`；
- `confirm_overwrite` 首次提交映射到 Worker 现有 `fail` 策略；无冲突直接排队；
- Python `OutputConflictError` 返回全部真实冲突路径，包括磁盘已有文件和活动/排队任务预留目标；
- Rust Host 保留 Worker 错误 `data`，前端只把 `output.failed + OutputConflictError + paths` 识别为可确认冲突；其他输出错误不触发覆盖确认；
- 主题化弹窗展示冲突数量及真实路径。取消保留输入、参数和当前工作台；确认后以同一冻结草稿仅重提一次，并映射到 Worker 现有 `overwrite`；
- 历史重试经过相同预检，每次都重新确认，不持久化覆盖授权。

Desktop IPC 仍为 v1，只增加可选错误数据字段的向后兼容使用；没有新增协议版本。

## 4. 硬件优化与任务冻结

模型库下方新增“硬件优化”面板：

- Worker 通过 CTranslate2 `get_supported_compute_types` 和真实 CUDA 设备数量返回能力；NVML 只提供 GPU 名称；
- 本机实测发现 Intel Core i7-14700KF、20 个物理核心、GPU 0 `NVIDIA GeForce RTX 5070 Ti`，CUDA 支持 `float16`、`int8_float16`、`float32` 等运行时能力；
- UI 开放自动/CUDA/CPU、GPU 索引、CUDA FP16/INT8+FP16/兼容 FP32、CPU INT8/FP32、1 至物理核心数的 CPU 线程；
- 推荐配置为自动设备、GPU 0、CUDA FP16、CPU INT8、最多 4 线程；不支持 FP16 时推荐项安全回退 FP32；
- 空闲修改立即按当前模型重载；失败恢复上一有效配置；忙碌时只成为新任务默认；
- `TranscriptionDraft`、持久化偏好和任务快照携带硬件配置；Worker 任务实体冻结解析后的模型/硬件组合，并只在任务边界切换；
- 历史重试沿用原硬件快照；设备/精度已不可用时在前端阻止并引导到模型工作台；
- `model.ready`、`task.queued` 和 `system.health` 都携带或校正真实设备、索引、计算类型和 CPU 线程。

Desktop IPC v1 按授权增加 `model.load`、`transcription.start`、`task.queued` 的可选 hardware 字段。旧客户端不传时继续采用既有自动 CUDA/FP16、否则 CPU/INT8/4 线程行为。Preset、语言、解码、防幻觉、SRT 时间轴、文本排版、文件命名和输出路径均未改变。
