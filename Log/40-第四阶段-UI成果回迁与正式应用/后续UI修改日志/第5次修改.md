## 2. 数据设计与实时来源

性能详情保留第 4 次修改的当前值、15 秒平均/峰值/低点/变化、负载轨和容量余量，并新增一个高密度“硬件与进程遥测”表，不再堆叠重复的设备/来源/时间卡片。

### CPU 与系统

- 处理器名称：Windows 注册表，失败时回退 `platform.processor()`。
- 系统报告频率：`psutil.cpu_freq()`；文案明确说明它不一定等于任务管理器的瞬时 Boost 频率。
- 物理核心、逻辑处理器、系统进程数和系统运行时间：`psutil`。
- Worker 线程数和句柄数：当前冻结 Worker 进程自采样。

### 系统内存与 Worker

- 已用、可用、物理内存总量、交换空间已用/总量：`psutil.virtual_memory()` 和 `swap_memory()`。
- Worker 常驻内存 RSS：当前 Worker 进程实测，不是浏览器模拟值。

### NVIDIA GPU 与显存

- GPU 核心利用率、显存控制器利用率、显存已用/总量、设备名称。
- GPU 温度、核心频率、显存频率、当前功耗/功耗上限、风扇比例、P-State、驱动版本。
- 上述 GPU 数据均来自本地 NVIDIA NVML；单个传感器不可用时该字段返回 `null`，不影响其他采样。

## 3. 明确没有伪造的信息

当前跨硬件和驱动无法稳定取得的字段没有显示：

- CPU 温度。
- 主板电压、机箱/水泵/主板风扇转速。
- DRAM 频率、插槽、时序和温度。
- Windows 共享 GPU 内存。
- WDDM 下 NVML 无法稳定报告的每进程 GPU 内存。

这些项目如果以后需要，必须另行评估厂商 SDK、Windows 性能计数器或其他特权采样方案，不得以静态文案补齐。
