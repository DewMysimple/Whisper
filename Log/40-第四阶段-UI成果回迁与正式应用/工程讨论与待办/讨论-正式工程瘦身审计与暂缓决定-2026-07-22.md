## 3. 各类文件的用途与历史价值

### 3.1 开发流程回溯价值最高

- `Log`：保存阶段记忆、每次 UI/功能修改、功能测试、报错处理、约束和讨论决定。
- `apps/web/src`、`apps/desktop/src-tauri/src`、`src/whisper_subtitle`：当前真实实现。
- `tests`、`apps/web/e2e`：解释功能行为、边界和回归门禁。
- `contracts`、`docs`、README：解释 IPC、架构和阶段规则。
- `Cargo.lock`、`pnpm-lock.yaml`、`requirements.txt`、`packaging/worker.spec`：解释依赖和构建方式。
- `.git` 和当前工作区差异：保存已有提交历史和当前未提交实现状态。

### 3.2 对运行或继续开发有用，但不是开发历史

- `whisper_env`：包含 faster-whisper、PyTorch、CUDA、PyInstaller 和 `hf.exe` 等开发工具。正式软件不直接依赖它，但源码测试和重建 Worker 需要它。
- 顶层 `models\huggingface`：用于源码模式和真实 GPU 开发测试。
- `node_modules`：用于前端构建和测试，可重新安装，但保留可避免再次获取依赖。
- `target\release\models`：正式模型工作台直接使用，不能作为普通缓存清理。
- `target\release\worker`：正式 Worker 及 CUDA、CTranslate2、音视频依赖，正式转录必须保留。
- 正式 Desktop EXE：当前唯一正式桌面入口。

### 3.3 对理解开发流程价值最低，但可用于构建加速或旧版本回滚

- `target\debug`：Rust Debug 依赖库、PDB、对象文件和增量编译缓存；删除后可重新编译。
- Release 的 `deps`、`build`、`.fingerprint`、`incremental`：Rust Release 编译缓存；不属于正式运行时主体。
- 内部检查点中的 `work`：PyInstaller 临时工作目录。
- 内部检查点中的 `env`、`candidate-dist`、`clean-final-dist`：旧 Python 环境或打包后的 Worker 依赖副本，包含大量重复 CUDA DLL。
- 旧 EXE/Worker 检查点：可用于紧急回退或行为对照，但不包含可阅读的旧源码，不能代替源码级版本历史。
- `.pytest_cache`、前端 `dist` 和 `test-results`：可重新生成的测试或构建产物。

内部检查点的目录名称虽然带有批次编号，但其主要内容是旧二进制、依赖和打包环境，而不是逐次源码快照。因此它们对“运行旧版本”可能有价值，对“理解代码如何演进”的价值明显低于日志、源码、测试和版本差异。

## 4. 重复文件核查

### 4.1 Turbo 模型

`large-v3-turbo` 的 `model.bin` 存在三份内容一致的物理文件，每份约 1.51 GiB：

1. Hugging Face `blobs` 缓存。
2. Hugging Face `snapshots` 快照。
3. 正式软件 `target\release\models\large-v3-turbo\model.bin`。

三份文件 SHA-256 均为：

`E76620F83D5F5B69EFD3D87E3DC180C1BD21DF9FBEBACFD4335E5E1EFCC018DA`

文件 ID 核查显示它们不是同一个硬链接，确实占用独立物理空间。前两份服务开发缓存，第三份服务正式应用；本轮决定全部保留。

### 4.2 CUDA、CTranslate2 与媒体依赖

相同的大型 DLL 同时存在于 Python 开发环境、正式 Worker 和多个旧 Worker 检查点。例如约 638 MiB 的 `cublasLt64_12.dll` 有七份内容一致的副本，其 SHA-256 为：

`71705A7CF0923F4AB034D0D2620BBFC989FF669AC3D79F868B7A7C597CA559C5`

这些重复主要来自每个 PyInstaller onedir 必须携带独立运行依赖，以及内部检查点保存了多轮完整 Worker 包。当前正式 Worker 和开发环境仍有明确用途；检查点副本虽可作为未来瘦身候选，本轮同样完整保留。

## 5. 曾讨论但未授权的均衡瘦身方案

只读审计曾形成约 **27 GiB** 的理论候选方案：

- 约 15.1 GiB：旧的大型内部检查点，仅保留最近的小型正式二进制回滚点。
- 约 9.8 GiB：Rust Debug 构建缓存。
- 约 2.1 GiB：Rust Release 的 `deps`、`build`、`.fingerprint` 等可再生中间产物。

该方案原计划保留正式 Desktop、正式 Worker、正式模型、开发模型缓存、Python 环境、前端依赖、源码、测试、日志和 Git 数据。理论上可将工程从约 37.4 GiB 缩减至约 10.4 GiB，但会让下一次 Rust 构建重新编译依赖，并失去部分旧二进制快速回退能力。

该方案现已明确暂缓，不构成未来执行授权。若以后重新考虑，必须重新统计当时的目录、哈希、进程和工作区状态，不得直接套用本次目标清单。
