# 报错处理 001：SRT 任务字段命名不一致

日期：2026-07-19。  
状态：已修复、已回归、已重建并启动唯一正式 EXE。

## 1. 用户可见现象

用户在转录工作台选择“中文转录”SRT 预设，加入媒体并点击“开始生成 SRT 字幕”后，页面顶部显示：

```text
invalid args `draft` for command `start_transcription`: unknown field `cue_gap_ms`, expected one of `maxCharactersPerLine`, `maxLinesPerCue`, `minCueDurationMs`, `maxCueDurationMs`, `maxCharactersPerSecond`, `cueGapMs`
```

任务没有进入队列，也没有开始模型加载、GPU 推理或文件写入。

## 2. 根因

正式 React 内部的 `SubtitleParameters` 使用 snake_case，前端 Tauri Bridge 在组装 `start_transcription` 参数时直接把整个对象放入 `output.subtitle`：

```text
max_characters_per_line
max_lines_per_cue
min_cue_duration_ms
max_cue_duration_ms
max_characters_per_second
cue_gap_ms
```

Rust Host 的 `BridgeSubtitleParameters` 明确使用 `#[serde(rename_all = "camelCase", deny_unknown_fields)]`，因此只接受：

```text
maxCharactersPerLine
maxLinesPerCue
minCueDurationMs
maxCueDurationMs
maxCharactersPerSecond
cueGapMs
```

`cue_gap_ms` 在 Tauri 命令参数反序列化阶段被判定为未知字段。报错发生在 Python Worker 之前，与中文 Preset、媒体文件、Whisper 模型、CUDA、字幕切分算法和输出路径无关。

当前 Bridge 会在正式任务请求中附带字幕参数，因此该边界错误不应被归类为仅影响某一个中文 SRT 预设的问题。

## 3. 为什么原测试没有发现

- 前端 Bridge 单元测试中的 `invoke` 模拟只使用 `requestId`，没有断言 `draft.output.subtitle` 的实际字段名；
- Rust 单元测试直接构造 `StartDraft` 结构体，绕过了 JavaScript JSON 到 Rust 的反序列化边界；
- 浏览器 E2E 使用 `MockDesktopBridge`，不经过真实 Tauri `start_transcription` 命令。

因此各层内部测试能够通过，但真正的跨语言字段契约没有被覆盖。

## 4. 修复内容

### 前端 Bridge

文件：`apps/web/src/bridge/tauriDesktopBridge.ts`

`toHostOutput` 不再原样传递 `subtitleParameters`，而是显式转换六个字段：

- `max_characters_per_line` → `maxCharactersPerLine`
- `max_lines_per_cue` → `maxLinesPerCue`
- `min_cue_duration_ms` → `minCueDurationMs`
- `max_cue_duration_ms` → `maxCueDurationMs`
- `max_characters_per_second` → `maxCharactersPerSecond`
- `cue_gap_ms` → `cueGapMs`

### 回归门禁

文件：

- `apps/web/src/bridge/tauriDesktopBridge.test.ts`
- `apps/desktop/src-tauri/src/worker_host.rs`

新增门禁：

1. 前端测试断言 `start_transcription` 的真实调用对象使用完整 camelCase 字幕字段；
2. Rust 测试断言合法 camelCase 对象能够反序列化；
3. Rust 测试断言重新放入 `cue_gap_ms` 后必须被拒绝。

这组测试直接覆盖本次缺失的跨语言边界，避免只验证 TypeScript 内部对象或 Rust 内部结构体。
