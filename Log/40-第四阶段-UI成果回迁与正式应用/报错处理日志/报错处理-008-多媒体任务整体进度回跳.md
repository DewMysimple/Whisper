# 报错处理 008：多媒体任务整体进度回跳

日期：2026-07-24。  
状态：已修复；单元、E2E、真实 CUDA 双媒体事件序列和正式 Desktop 验收通过。

## 1. 现象

一个任务包含多个媒体时，整体进度会随转录增加，但在切换到下一个媒体后突然变小，随后再次增长。单媒体任务不容易观察到该问题。

## 2. 根因

Worker 正确按每个媒体重复发送：

`transcription.running → postprocess.running → output.writing`

旧 Desktop Bridge 却把这三个阶段分别映射到整批任务固定的 `19–78% / 79–88% / 89–96%`。因此第一个媒体写入输出后整体进度接近 96%，第二个媒体开始转录时又被映射回较低区间。

问题位于前端事件解释层，不是 Worker、模型、CUDA、性能采样或转录算法倒退。

## 3. 修复

进度改为“任务准备 + 按媒体等分 + 单媒体阶段”的累计模型：

- 准备 0–10%；
- 媒体处理 10–97%，按 `current / total` 的真实媒体位置推进；
- 单媒体内用真实 `media_progress_percent` 和阶段推进；
- 稀疏事件保留最近值；
- 失败、跳过和晚到事件不造成回退；
- 最终汇总为 99%，完成事件为 100%。

每个任务独立维护跟踪状态，并在终态释放。没有用 `Math.max` 对错误的绝对阶段映射进行表面遮盖，而是修正了多媒体累计语义。

同时修复任务完成后“任务汇总”仍不打勾的问题：步骤边界使用包含式完成判断，任务完成或 100% 时全部步骤进入完成态。

## 4. 测试与证据

单元测试覆盖：

- 第一个媒体写入后第二个媒体启动；
- 缺失单媒体百分比的稀疏事件；
- 晚到的较低百分比；
- 当前媒体失败；
- 99% 汇总与 100% 终态边界。

全量结果：

- Vitest 16 个文件、64 项通过；
- Playwright 9/9；
- Python 294 项通过；
- Rust 23 项通过，3 项系统副作用测试忽略。

真实 `large-v3-turbo + CUDA FP16` 双媒体事件经同一算法转换后为：

```text
2, 6, 10, 10, 10, 41, 41, 49, 54, 54, 54, 56, 56, 93, 97, 99
```

第一个媒体输出事件后紧接第二个媒体开始事件，整体值保持 56%，没有回跳；任务最终真实完成并生成两个输出。

证据位于：

`build\batch23-validation\runs\20260724-192655`
