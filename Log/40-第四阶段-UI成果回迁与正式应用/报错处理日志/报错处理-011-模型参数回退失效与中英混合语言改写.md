# 报错处理 011：模型参数回退失效与中英混合语言改写

日期：2026-07-26  
状态：参数链路与后处理已修复；单窗口密集 code-switch 的模型限制已明确

## 用户可见现象

在中文防幻觉模式下，同一复杂媒体使用 Large‑V3 与 Large‑V3‑Turbo 会出现：

- 英语对白被中文改写；
- 繁体字混入简体文本；
- `�` 乱码；
- `，。` 等错误标点；
- 长短语机械循环；
- Turbo 出现捏造英文形态。

这不是单一模型优劣问题，两个模型的错误类型不同。

## 根因

1. 四个 Preset 固定传入 `language=zh/en`，格式选择同时限制了模型语言令牌。
2. Temperature 只有标量 `0.0`。虽然配置了 compression/log probability 阈值，faster-whisper 没有第二个温度候选时无法执行真正的 fallback。
3. 防幻觉版本的 `log_prob_threshold=-1.5` 反而比标准版更晚触发置信度异常。
4. 中文标点函数曾对整行全局替换，破坏混排英语的标点语义。
5. 旧后处理没有繁转简、`U+FFFD` 清理和长短语循环规则。
6. 首个整改候选 `multilingual=True` 在真实样本中暴露出 faster-whisper 1.2.1 的逐 30 秒单语言令牌限制，并会误跳韩语，因此没有作为最终方案发布。

## 修复

- V3/Turbo 改为多窗口自动检测稳定主语言，Preset 语言仅用于排版。
- 固定 `task=transcribe`，不调用 `translate`。
- V3 使用完整温度阶梯，Turbo 将高温上限限制为 `0.6`。
- 防幻觉阈值校准为 compression `2.0`、log probability `-1.0`、no speech `0.6`。
- 引入 OpenCC `t2s`、非法字符过滤、上下文标点和三次以上精确短语循环折叠。
- 小模型继续使用旧参数，避免未经验证的行为扩散。
- UI 明确说明格式语义和模型 code-switch 边界，不再承诺逐句多语言完美保留。

## 回归门禁

- 四 Preset 的 `'`、`’`、TXT、Markdown、SRT 与无词级时间戳降级链继续通过。
- 验证 V3/Turbo 派生参数、小模型旧参数、手动 Temperature 覆盖。
- 真实完整媒体两模型 CUDA FP16 验收。
- 315 Python、28 Rust、77 Vitest、10 Playwright 通过。
- 正式 Worker 环境检查、OpenCC 冻结依赖、正式 Desktop 启动/关闭通过。

## 影响边界

- Desktop IPC 仍为 v1；`effective_parameters` 继续使用既有通用对象。
- 不改变 SRT 词级时间轴、输出路径、文件命名、冲突策略、模型文件或硬件冻结。
- 未改写任何已有输出及三份取证文件。

## 遗留风险

Whisper 的语言令牌仍以解码窗口为粒度。若中文和英文在同一窗口内高频切换，模型可能按主语言改写其中一段；V3 在本样本的短英语对白上仍比 Turbo 更明显。若以后继续整改，应建立多说话人、多窗口标注集并评估“按语音段重新检测语言”，不得用硬编码词典或全局替换伪造正确结果。
