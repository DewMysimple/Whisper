# 跨阶段 UI 契约与防不同步门禁

建立日期：2026-07-18。

## 目的

本规则用于防止第三阶段 HTML/CSS 源码与第四阶段正式 React UI 出现“整体相似但细节、文字或真实语义不同步”。它补充《代码迁移与验收规则》和《后续 UI 修改单批次标准流程》，优先约束以后所有回迁轮次。

## 根因结论

第一次 UI 回迁中暴露的问题并非 HTML 代码无法读取，而是迁移过程存在以下缺口：

- 只建立了页面和组件级映射，没有把可见文字、时间范围、单位、区域不存在性等逐项登记。
- “正式功能事实优先”被错误理解为可以自行改变设计语义。
- 测试验证了页面存在、指标切换和部分尺寸，却没有覆盖精确文案与数据时间窗口。
- 截图和整体观感曾承担了超出其能力的验收职责。

## 四类差异账本

第三阶段源码中的每一项差异必须且只能登记为：

| 类型 | 处理方式 | 是否需要用户批准 |
| --- | --- | --- |
| 精确回迁 | React 中保持可见文字、结构、样式、数量、顺序和无障碍语义 | 否，属于既定授权 |
| 真实数据映射 | 保持设计结构与语义，用正式状态替换演示值 | 否，但必须测试数据来源 |
| 纯演示排除 | 不迁入模拟 Worker、任务、文件、性能和输出行为 | 否，但必须写明排除项 |
| 功能冲突待决 | 暂停该冲突项，报告影响和方案 | 是，不得自行决定 |

不得使用“正式工程更方便”“现有组件原本如此”或“看起来接近”作为未登记偏离的理由。

## 功能事实优先的准确含义

功能事实优先只意味着：

- 不破坏 Python、IPC、Preset、任务和输出契约。
- 不把模拟数据伪装成真实数据。
- 不为了静态外观删除必要功能。

它不意味着可以静默改变第三阶段的可见文字、时间语义、单位、结构或交互位置。遇到冲突应保持正式功能安全，同时把设计项标为待决并报告用户。

## 强制迁移产物

每轮回迁在实现前必须生成一份逐页差异账本，至少包含：

- 第三阶段文件、选择器或代码位置。
- 正式 React 组件和状态来源。
- 可见文字、单位、时间范围和状态名。
- 关键结构、DOM 数量、网格行列、尺寸、字号和断点。
- 四类差异中的归类。
- 需要的自动测试。
- 未实现或待用户决定的原因。

只写“性能页已迁移”或“样式已对齐”不再满足门禁。

## 强制测试

- 精确文案测试：断言第三阶段规定的可见文字和帮助说明，并断言不得出现未经批准的替代文字。
- 结构测试：断言必须存在、必须不存在、区域顺序和网格行列。
- 计算样式测试：读取最终字号、尺寸、间距和关键 Token。
- 真实状态测试：证明数据来自正式 bridge/store，不来自原型常量。
- 语义一致性测试：时间范围、单位和状态文字必须与实际数据窗口和状态一致。
- 截图测试：只辅助发现遮挡、溢出、裁切和主题观感。

## 冲突示例与当前已知偏差

第三阶段性能页明确要求 `15s / 7.5s / 现在` 和“时间范围 15s 至现在”。正式实现却使用每 2 秒采样、最多 60 次历史，并显示“60 次前 / 30 / 现在”，实际约为 120 秒范围。

这是第一次回迁产生的未经批准语义偏离。用户已在第 3 次修改中授权整改；正式前端现按真实时间戳维护最近 15 秒滑动窗口，并以约 190ms 的前端轮询目标填充 80 列，不再用“60 次”冒充时间范围。该冲突已关闭。

## 反向调和门禁

第三阶段通常是视觉事实来源，但用户可以明确授权一次“以正式软件 UI 为基准”的反向调和。此类操作不是自动同步，必须：

- 记录用户授权、调和方向和新快照名。
- 从正式 React 组件、最终 CSS 和状态结构抽离，不能根据截图重画。
- 只同步 UI 表现层；正式 Worker、IPC、任务和文件行为仍不得进入 HTML。
- 对正式真实状态使用明确演示值承载结构，不得在 HTML 中声称实时检测。
- 调和完成后重新冻结共同基线；此后两边再次恢复非自动同步。

第 3 次修改按此门禁形成 `UI-2026-07-18-R02`。

## 完成声明

只有逐页差异账本没有未登记项、所有待决冲突获得用户决定、代码测试通过且正式桌面产物验收完成，才能声明该快照“完整回迁”。
