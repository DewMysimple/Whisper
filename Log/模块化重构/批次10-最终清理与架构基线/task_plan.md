# 批次 10：最终清理与架构基线

## 目标

审计并整理批次 0–9 形成的新结构，建立可长期维护的架构、文件、兼容性和发布基线。

## 边界

- 公开兼容入口删除前必须取得用户明确确认。
- 不修改转录参数、golden 语义或 UI 设计。
- 不修改或删除 `.workbuddy`。
- 不自动暂存、提交、打标签、推送或发布。
- 保留批次 0–9 的未提交前置成果，不创建无法携带这些成果的隔离 worktree。

## 阶段

- [complete] 1. 冻结批次 10 起点，审计仓库结构、旧入口、引用和命名。
- [complete] 2. 形成公开兼容入口删除/保留清单，提交用户确认。
- [complete] 3. 整理非公开文件命名、目录职责和产物保留策略。
- [complete] 4. 新增架构说明、依赖方向和 preset/引擎/UI 扩展指南。
- [complete] 5. 根据用户确认处理兼容入口，生成迁移映射与最终模块树。
- [complete] 6. 运行 pytest、真实中英文、四 preset benchmark、安装和 GUI 验证。
- [complete] 7. 对照批次 0 生成最终差异/性能报告并完成清理。

## 验收

- 旧重复实现和无引用文件被删除，或记录明确保留理由。
- 文件名统一为小写 snake_case，公开兼容文件除外。
- 架构依赖方向、扩展方式和资料保留策略有稳定文档。
- 测试、golden、真实音频、CLI、GUI、安装及性能门禁通过。
- 输出最终模块树、迁移映射、兼容性和性能对比报告。

## 遇到的错误

| 错误 | 尝试次数 | 处理 |
| --- | ---: | --- |
| 普通 worktree 无法携带批次 0–9 的未提交前置成果 | 1 | 不自动提交，记录原因并在当前工作区继续 |
| 移除兼容测试时误删仍被 JSONL 断言使用的 `Path` 导入 | 1 | 恢复定向测试所需导入，`106 passed` |
| snake_case 门禁未把 Python 标准 `__main__.py` 视为合法 dunder 文件 | 1 | 将 `__init__.py`、`__main__.py` 一并列为允许项 |
| benchmark 首次汇总仍读取已删除的 `legacy_preset` 局部变量 | 1 | 改用类型化注册表的 `get_postprocess_label()`，失败样本不计入最终结果 |
| 首次 wheel 复用了忽略目录 `build/lib` 中的旧 Core/GUI 文件 | 1 | 将旧 build 和不合格安装送入回收站，执行干净构建并检查 wheel 成员 |
| 首次安装环境的 `check` 未显式指定工作区模型目录 | 1 | 复验时设置 `WHISPER_SUBTITLE_MODEL_DIR`，区分安装正确性与模型部署位置 |
