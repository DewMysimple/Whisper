# WhisperSubtitle 项目优化评估计划

## 目标

基于当前代码与构建/测试现状，找出可落地的优化项，并给出能平滑过渡到模块化乃至架构替换的分阶段路线。

## 阶段

- [complete] 1. 盘点仓库结构、技术栈、入口、依赖与构建方式
- [complete] 2. 检查核心业务链路、耦合点、状态与错误处理
- [complete] 3. 检查测试、性能、安全、可维护性和发布流程
- [complete] 4. 验证重点问题并按收益/风险/成本排序
- [complete] 5. 输出短期优化清单与模块化/架构演进路线

## 范围约束

- 本轮以只读诊断和建议为主，不修改业务代码。
- 保留用户现有未提交改动，不覆盖 `.claude/settings.local.json`。

## 错误记录

| 错误 | 次数 | 处理 |
|---|---:|---|
| 初次仓库探测因 `rg` 无匹配返回 1，导致命令整体显示失败 | 1 | 后续允许无匹配或拆分命令 |
| `git ls-files` 的中文路径被 Git 引号转义，PowerShell `Test-Path` 判为非法路径 | 1 | 已取得所需跟踪清单；后续使用 `core.quotepath=false` 或文件系统枚举 |
| PowerShell 将 `foreach` 后直接接管道解析为空管道元素 | 1 | 改为先收集 `$rows` 再格式化输出 |
| 直接运行核心 CLI 的模拟测试因 Windows GBK 控制台无法编码 emoji 而崩溃 | 1 | 这是产品缺陷证据；测试时显式设 `PYTHONIOENCODING=utf-8` 继续验证其余流程 |
