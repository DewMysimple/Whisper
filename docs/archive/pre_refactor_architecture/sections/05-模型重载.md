### 问题本质

GUI 进程（PyQt5 常驻）与转录进程（core 子进程）是两个独立进程。模型加载（4.3s）的生命周期绑死在 core 子进程里——子进程结束，模型销毁、显存释放，下次点"开始"又重来。

实测：进程启动+import ≈1s，模型加载 ≈4.3s，**每次点"开始"付 5.3s 重载税**。

### 影响场景

- 单次批量（一次选文件夹跑 N 个）：不痛，进程内复用模型。
- 跨次点击（跑完一批再跑一批）：痛，每次 5.3s 预热。
- 频繁小任务：最痛。

### 三种解法（取舍）

- **思路 A — 常驻转录进程（推荐）**：core 改成常驻 worker，stdin 接收任务，干完不退出。首次 5.3s 后，后续点开始 0 延迟。代价：模型常驻占显存（~1.5–2GB）、需设计 stdin/stdout 协议、需处理崩溃重启。
- **思路 B — GUI 进程内直接转录**：faster-whisper 搬进 GUI 进程，启动时加载一次。代价：转录阻塞主线程需 QThread；torch import 顺序坑进 GUI；大重构。
- **思路 C — 治标**：靠系统层优化减少加载时间。但 4.3s 主要是 GPU 权重上传 + CUDA JIT，非磁盘 I/O，收益小，不推荐。

**当前决定**：暂不处理（用户优先做三版演进）。
