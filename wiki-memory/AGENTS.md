# 工程 Agent 记忆维护协议

## 记忆层

- `当前状态/`：当前有效事实；每个主题只保留一个 active 页面。
- `决策/`：架构、技术选型和工程边界；旧决策保留并标记 `superseded` 或 `deprecated`。
- `知识/`：稳定的模块、流程、规范和运维知识。
- `日志/`：一次实质任务的追加式历史记录。
- `历史归档/`：迁移前旧 `Log` 的只读追溯资料，不是当前事实来源。

## 会话读取顺序

1. 读取本文件和项目根目录 `AGENTS.md`。
2. 读取 `当前状态/项目概览.md`、`系统架构.md`、`当前约束.md`、`当前待办.md`。
3. 读取相关 active 决策和知识页。
4. 只有需要追溯时读取最近日志或历史归档。

目标是让默认启动上下文保持精简，不为了“完整”读取全部历史。

## 事实优先级

1. 当前工作树中的代码、配置、schema 和测试；未提交代码必须标记为开发中。
2. 当前 `docs/` 和根 README。
3. 已记录且仍与代码一致的历史结论。
4. 讨论、候选方案和未授权待办只能作为 proposed/deferred 资料。

发生冲突时不要静默覆盖：在日志中说明冲突，并更新对应 active 页面或决策。

## 写入规则

- 长期页面和日志使用 YAML frontmatter：`type`、`status`、`kind`、`importance`、`updated`、`topic`、`source_logs`。
- 每篇长期页面只记录会影响未来工作的结论、边界、入口和来源。
- 完成实质任务后新增 `日志/YYYY-MM-DD-任务标题.md`，记录目标、检查范围、变更、验证、遗留问题和待确认记忆。
- 日志封存后不改写；需要更正时新增日志并链接旧日志。
- Obsidian 链接使用 `[[路径|别名]]`，记忆路径使用 `/`。
- 不记录密钥、令牌、完整聊天、内部推理或大段命令输出。

## 任务标签

日志只使用一个主要 `kind`：`feature`、`ui`、`bug`、`discussion`、`test`、`maintenance`。

## 固定操作

- `记忆检索 <关键词>`：先查当前状态和相关索引，再查知识页与历史。
- `记忆同步`：新增日志，提出待确认长期记忆，并在确认后更新 active 页面。
- `记忆体检`：运行 `python wiki-memory/工具/memory_lint.py check`。
- `记忆索引`：运行 `python wiki-memory/工具/memory_lint.py index`。

任何整理都不得修改生产代码、模型、用户工作区或未授权的 Git 历史。
