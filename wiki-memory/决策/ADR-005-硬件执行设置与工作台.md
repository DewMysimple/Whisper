# ADR-005：硬件执行设置与工作台

用户于 2026-09-20 明确要求新增 GPU／CPU 硬件优化工作台，并让模型／参数工作台参考任务监控与性能监控风格、统一模型卡片尺寸；随后明确授权更新完整 `dist` 便携版。本决策取代 ADR-003／ADR-004 中“人工硬件配置继续退役”的限制，不恢复旧硬件偏好字段。

## 设置与运行时边界

- `HardwareView` 提供自动选择、GPU 加速、节省显存、CPU 推理四个快捷方案，以及执行设备、GPU 编号、计算精度、CPU 推理线程四项设置。快捷方案根据实际能力选择可支持的精度；无法支持时不可选，不能假装已经启用。
- 新设置由 `executionOptions` 独立持久化；旧 `hardware`／`hardware_preferences` 不迁移回产品。浏览器预览继续使用独立存储，演示能力不进入正式桌面。
- `transcription.start.params.execution` 是可省略的部分对象，schema 定义名为 `ExecutionSettings`。`device` 为 auto／cuda／cpu，`device_index` 为 0–31，`cpu_threads` 为 0–256；支持的精度枚举由 schema 统一约束，具体设备可用值由 CTranslate2 返回。
- 省略设置保持历史自动行为：CUDA 0 优先 float16、否则 float32；没有 CUDA 时 CPU int8。CPU 默认 4 线程，CUDA 默认 0。省略 `cpu_threads` 继承上述默认，显式 0 交给运行时自动选择，二者不能合并。
- `domain/execution.py` 校验 Python 输入；Web 和 Rust Host 读取共享 schema。`HardwareDetector.resolve` 检查设备及精度，显式 CUDA 不可用、设备编号错误或精度不支持必须明确失败，不能静默改用 CPU 或另一精度。CPU 只接受设备编号 0。
- Worker 在提交时冻结解析后的 `HardwareInfo`；队列执行和缓存都使用该对象，不在运行时重新读取 UI 设置。模型与实际硬件配置一致才复用缓存，变化时按串行队列顺序重新加载。线程字段直接传入 faster-whisper 构造器，不修改系统进程优先级、系统电源计划或全局线程环境。

## 能力与展示

继续使用空参数 `system.environment` 查询，在原结果上增加可选 `hardware_capabilities`，包含逻辑处理器数量和 CPU／CUDA 设备编号、名称、可用精度。能力探测失败时返回 `hardware_error`，保留原有 available／errors 环境结果。CTranslate2 是能力依据，NVML 只补充名称等元数据。

模型／参数工作台沿用任务页的连续分段导航、性能页的面板与紧凑标题层级，参数分组保留现有控制语义。模型卡采用等宽网格和等高行，长路径在卡片内换行，不由内容长短改变卡片外框。硬件页同样复用 SegmentedCard、SummaryText 和公共按钮，页面 CSS 独立归属且受样式检查约束。

## 兼容与验证

不增加 command、不改 schema_version 和任务生命周期；`model.load`／`model.unload` 继续只保留 v1 兼容，不能携带新执行设置。新 `execution` 与公开推理参数需要配套 Host／Worker，旧冻结版本不支持。正式交付须同时重建前端、Tauri Host、冻结 Worker、便携目录与 ZIP，并验证 EXE 持续监管 Worker；不得只替换桌面 EXE。

验证覆盖参数边界、实际能力错误、独立保存、冻结提交、构造器传递、缓存复用、主题与响应尺寸，及本地 Turbo 的真实 CUDA／CPU 媒体输出。快捷方案是设置组合，不承诺特定提速倍数；识别结果和吞吐仍由硬件、媒体、模型及参数共同决定。
