# 模块化重构规划依据

- 前三阶段已完成稳定性修复、Python 包结构、统一 CLI、GUI 设置持久化、依赖重建、71 条 pytest 用例、四 preset golden 与性能基线。
- 当前工作区仍包含前三阶段未提交修改，正式重构前需要先建立可回滚基线。
- 四个 Core 脚本为 320–377 行，两两文本相似度约 78%–89%，存在大量完全相同函数。
- GUI 文件 1189 行，`_build_ui()` 单方法 509 行，是第二个主要拆分对象。
- CLI preset 名称与 GUI/config ID 不完全一致，且 CLI 和 presets 分别维护映射，存在漂移风险。
- Core 同时承担模型、推理、文件发现、后处理、输出、日志和退出码，需先定义应用层契约再移动代码。
- `PROJECT_ROOT`、固定 `whisper_env` 和源码路径假设影响安装后运行；四个 Core 在导入时修改环境变量并全局忽略 warning。
- Torch 只用于 CUDA 检测，torchaudio/torchvision 未被业务源码使用；依赖瘦身收益高但风险较大，应独立成批、放在架构稳定之后。
- 最终计划包含批次 0–10 共 11 批；每批均有目标、工作内容、禁止事项、验收标准和可直接发送的触发语句。
