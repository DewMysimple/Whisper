## 3. 输入来源规则

状态：`Accepted`。

建议未来 `InputSource` 至少包含 `path`、`kind=file|directory` 和 `origin=dialog|drop|paste|manual`。

规则：

1. 手工输入先去除首尾空白。
2. 只有首尾均为 `"` 时才剥离一层外引号。
3. 路径始终作为结构化字符串传递，不构造 shell 命令。
4. 文件夹继续采用当前递归发现和目录内排序规则。
5. 多来源以 Windows 规范化、不区分大小写的键去重，保留第一次加入顺序。
6. 非法来源保留在列表中并显示具体错误，不能静默丢弃。
7. 同名输出必须在任务启动前完成冲突规划。

## 4. 自定义模式状态机

状态：`Accepted`。

```text
选择 preset
  → base_preset_id = 选中 preset
  → overrides = {}
  → mode = preset

修改任一可编辑参数
  → 记录与基础 preset 不同的 overrides
  → mode = custom

恢复 preset
  → overrides = {}
  → mode = preset

任务入队
  → 冻结 base_preset_id + overrides + effective_parameters
```

已经入队或执行中的任务不受面板后续编辑影响。自定义模式不写回四 preset 注册表，也不自动更新 golden。

## 5. 首批参数白名单

状态：`Accepted`。

以下是参数 UI 的首批推荐安全边界。批次 1 需要把类型和范围写入 schema；批次 2 需要由 Python Worker 再次校验。范围可以经测试收紧，未经评审不能扩大或移除校验。

| 参数 | 类型 | 初始 UI 范围/形式 | 说明 |
| --- | --- | --- | --- |
| `beam_size` | int | 1–20 | 解码搜索宽度 |
| `best_of` | int | 1–20 | 候选数量 |
| `patience` | float | 0–5 | beam search patience |
| `length_penalty` | float | 0–2 | 长度惩罚 |
| `temperature` | float | 0–1 | 首批只允许单值，不开放温度序列 |
| `compression_ratio_threshold` | float | 0–10 | 压缩率阈值 |
| `log_prob_threshold` | float | -10–0 | 对数概率阈值 |
| `no_speech_threshold` | float | 0–1 | 无语音阈值 |
| `condition_on_previous_text` | bool | 开/关 | 是否使用前文上下文 |
| `min_silence_duration_ms` | int | 0–10000 | VAD 最短静音时长 |

P0 中保持锁定、不允许直接编辑：

- `language`：由来源 preset 决定，避免“中文 preset + 英文参数”的语义混乱。
- `task`：保持 `transcribe`。
- `word_timestamps`：保持当前 `False`，波形/字幕编辑另立批次评估。
- `vad_filter`：保持当前 `True`。
- `max_speech_duration_s`：保持当前注册表值。
- `initial_prompt`：首批不开放；它会直接影响输出语义，后续如开放需单独需求和 golden 策略。

## 6. TXT/Markdown 输出模型

状态：`Accepted`。

推荐使用“兼容模式 + 自定义模式”，而不是直接替换当前输出规则。

### 兼容模式（默认）

- 完全沿用当前 `OutputPlan`。
- 默认写媒体旁 `Text/<name>.txt`。
- 指定强制目录时仍保留当前源目录 TXT 备份。
- “桌面输出”继续生成固定桌面 TXT 和内容相同的 Markdown。

### 自定义模式

协议允许分别表达：

```text
txt.enabled
txt.directory
markdown.enabled
markdown.directory
preserve_source_txt
conflict_policy
```

UI 默认提供一个“输出根目录”，TXT/Markdown 默认在根目录下使用 `Text`/`Markdown` 子目录；高级设置允许分别覆盖两个目录。这样既保持简单交互，也覆盖用户希望分别调整 TXT 和 MD 路径的需求。

推荐冲突策略：执行前检测并默认询问；批量无人值守场景可显式选择 `fail` 或 `auto_rename`。不得默认静默覆盖不同来源的同名文件。

用户验收结论：

1. 接受“共享根目录 + 可选独立覆盖”。
2. Markdown 在新 UI 中默认关闭，以保持当前行为。
3. 兼容模式保留源媒体旁 TXT；自定义模式由开关决定。

## 7. Windows 与 WebView2 策略

状态：`Accepted`。

支持范围：

- 正式支持和完整验收：Windows 11 x64。
- 不支持且不做兼容验证：Windows 10 22H2 x64 及其他 Windows 10 版本。
- 暂不支持：Windows x86、Windows on ARM、macOS、Linux。

推荐 WebView2 策略：

- 使用 Evergreen WebView2 Runtime，不依赖外部 Microsoft Edge 浏览器。
- NSIS 安装版使用 `offlineInstaller`，保证离线安装；官方资料显示会增加约 127 MB。
- 便携目录启动前检测 Evergreen Runtime；缺失时给出随包离线安装器，而不是静默联网。
- 暂不内嵌 Fixed Version Runtime；官方资料显示它会显著增大包体，并增加自行维护安全更新的责任。

## 9. Worker 与安装/便携布局

状态：`Accepted`。

### Worker

- 首选 PyInstaller `onedir`，而不是 `onefile`。
- 理由：CUDA/CTranslate2 DLL 可见、模型加载启动更直接、诊断和增量更新更容易；PyInstaller 官方也建议先验证 one-folder，再考虑 one-file。
- Tauri 通过 `externalBin` 管理 Worker sidecar，Rust Host 持有进程和协议读写权限。
- 前端不直接获得通用 shell/sidecar spawn 权限。

### 安装版

- 首选 Tauri NSIS `-setup.exe`，默认 per-user；是否提供 per-machine 由发布批次决定。
- 首选 WebView2 `offlineInstaller` 以支持离线安装。
- 安装器负责快捷方式、卸载、运行时检查和版本信息。

### 便携目录版

```text
WhisperSubtitle/
├── WhisperSubtitle.exe
├── worker/
│   ├── whisper-subtitle-worker.exe
│   └── _internal/
├── models/
├── runtime/
├── logs/
└── WebView2RuntimeInstallerX64.exe
```

- 不包含开发用 Node/Rust/Python 工具链。
- 不复制 `whisper_env`。
- 运行时路径从可执行文件/模式标记解析，不保存旧电脑绝对路径。
- 模型目录保持可移动；用户数据和日志需区分安装模式与便携模式。
