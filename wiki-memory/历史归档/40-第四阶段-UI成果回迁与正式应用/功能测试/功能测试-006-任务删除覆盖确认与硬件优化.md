# 功能测试 006：任务删除、覆盖确认与硬件优化

测试日期：2026-07-22。  
状态：自动化、真实能力查询、CUDA FP16/INT8+FP16、最终冻结 Worker 与正式 EXE 验收通过。

## 1. 测试目标

验证三组行为在正式本地 Tauri/Worker 链路中同时成立：历史删除必须原位二次确认且不触碰磁盘文件；同名输出必须在任务创建前展示真实冲突并由用户单次授权覆盖；模型与硬件组合必须按任务冻结并在队列边界切换。

## 2. 删除与覆盖判定

- 单条、已完成批量、异常批量入口第一次激活不删除；4 秒内第二次激活才删除；
- Escape、点击其他区域、切换工作台或超时取消待确认；活动任务无入口且状态层拒绝；
- 删除历史不调用媒体、模型、输出文件删除或移动；
- `confirm_overwrite` 无冲突时直接排队；
- 磁盘已有目标和队列预留目标都进入结构化 `paths`；
- 取消覆盖不创建失败历史并保留草稿；确认只把同一草稿映射为一次 `overwrite`；
- 自动重命名、媒体旁副本、TXT/Markdown/SRT、自定义根目录和冲突写入规则保持回归通过。

## 3. 硬件判定

- 能力来自真实 CTranslate2，不根据 GPU 名称模拟；
- 自动/CUDA/CPU、设备索引、计算精度和线程范围均经过前端、Rust Host、Python 协议和 Worker 验证；
- 本机 GPU 0 同时支持 FP16 与 INT8+FP16，两种配置均真实加载并完成短媒体任务；
- `task.queued.data.hardware` 与提交配置一致，任务输出完成后 `system.health` 仍回报真实加载配置；
- 混合硬件队列按任务顺序发生模型缓存替换，运行中任务不受之后默认配置变化影响；
- 不可用 GPU、精度或 CPU 线程越界被拒绝；历史重试在硬件缺失时转到模型工作台。
