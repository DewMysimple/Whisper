执行日期：2026-07-20。  
状态：已完成代码、自动化回归、Tauri Release 构建和正式桌面烟测；等待用户目视验收。

## 1. 用户授权与现象

用户明确要求：

> 执行任务后，切换到性能监控工作台，是要切换到性能监控工作台的置顶。

第 12 次修改已经在任务成功提交后切换到“性能监控”，但浏览器文档仍保留转录工作台原有的纵向滚动位置。用户从转录页下部点击开始后，性能页可能直接显示中部或底部，而不是页面顶部。

本次是正式软件第 13 次 UI 交互修改，只修改 `F:\WhisperSubtitle`；没有同步第三阶段 `C:\Users\Administrator\Desktop\WhisperUI`。

## 2. 修复

文件：`apps/web/src/App.tsx`

监听正式 `activeView`。当目标页面变为 `performance` 时，在页面提交后执行：

```text
window.scrollTo({ top: 0, left: 0, behavior: 'auto' })
```

最终行为：

- 新任务成功提交后切换到性能监控，并立即显示性能页顶部；
- 重试任务成功提交后沿用同一切换路径，同样显示顶部；
- 手动点击“性能监控”也会从该工作台顶部开始；
- 前置校验失败、Worker 拒绝或任务未成功提交时，仍不会误切换页面；
- 不使用平滑滚动，避免先展示错误位置再产生可见位移。

## 3. 回归测试

React 测试新增断言：任务提交并进入性能监控时，必须调用一次顶部复位，参数严格为 `top: 0`、`left: 0`、`behavior: auto`。

Playwright 使用真实页面滚动验证：

1. 先把完整转录工作台滚到文档最底部；
2. 确认 `window.scrollY > 0`；
3. 不让测试框架代替应用滚动，直接触发“开始本地转录”；
4. 确认切换到性能监控；
5. 断言最终 `window.scrollY === 0`。
