# 第 14 次修改：输出文件丢失纳入异常历史

执行日期：2026-07-20。  
状态：已完成代码、前端/Rust/E2E 回归与 Tauri Release 构建；等待用户用已删除或已移动的真实输出记录验收。

## 1. 用户授权与语义

用户明确要求：“任务记录”中的“异常历史”还应包括已经无法浏览到输出文件的任务。例如任务曾经成功输出，但文件后来被删除或移动，任务记录无法再定位该文件，也应算异常历史。

本次按以下正式语义实现：

- `failed`、`cancelled` 继续属于异常历史；
- 状态为 `completed`，但没有记录输出路径，属于异常历史；
- 状态为 `completed`，但任一记录输出路径已经不是可访问文件，属于异常历史；
- 文件被删除、移动或改名都会使原记录路径失效，因此统一标记“输出文件已丢失或移动”；
- 不扫描磁盘、不猜测搬家后的新位置，不读取媒体或输出内容；
- “清除异常历史”只删除软件内的历史快照，不删除任何实际文件。

本轮只修改 `F:\WhisperSubtitle`，没有同步第三阶段 `C:\Users\Administrator\Desktop\WhisperUI`。

## 2. 实现

### 本地路径审计

新增 Tauri 本地 Host 命令 `inspect_output_paths`，使用 Windows/Rust 文件系统元数据检查记录路径是否仍为文件。该命令只返回：

```text
path + exists
```

它不进入 Python Worker，不修改 Desktop IPC v1，也不搜索目录。

每次进入完整“任务记录”工作台时：

1. 收集所有已完成任务的输出路径；
2. 去重后一次性交给本地 Tauri Host 检查；
3. 所有记录输出都存在时标记 `available`；
4. 没有输出或任一输出不存在时标记 `missing`；
5. 审计期间暂时禁用两个历史清理按钮，避免用户在结果返回前把缺失输出误当普通完成历史清除。

如果用户点击“定位输出”或打开预览时才发现路径失效，该任务也会立即改为 `missing`。

### 任务记录 UI

输出缺失任务：

- 状态图标改为异常警告；
- 阶段文案显示“输出文件已丢失或移动”；
- 详情状态显示 `OUTPUT MISSING`；
- 详情明确说明文件已被删除、移动或改名，无法预览；
- 不再显示无效的“定位输出”按钮；
- 计入顶部“需要处理”和“清除异常历史”数量；
- 不再同时计入正常“已完成”数量和“清除已完成历史”数量。
