## 3. 双层任务监控

性能监控中的任务卡改为 `LIVE TASK MONITOR` 结构，同时显示：

- 真实整体任务进度；
- 真实当前媒体进度；
- Worker 总耗时和当前媒体耗时；
- 当前阶段、媒体计数和当前文件；
- 其他排队任务数量。

单媒体进度未知时使用不确定状态，不伪造百分比。前端秒表以 Worker 真实秒数为基线，在事件间独立计时；任务进入完成、失败或取消状态时立即冻结。

新增 `monitoredTaskId` 后，终态任务画面会继续保留。只有下一任务产生第一条真实运行进度时才切换，单纯排队不会覆盖上一任务；被监控历史删除后再回退到活动任务或空状态。

运行中和排队任务可在软件内通过主题化确认框“终止任务”，仍调用既有安全取消链路，没有增加暂停状态或暂停 IPC。

## 4. 真实输出路径与打开目录

Worker 在每个媒体成功写入后，通过 `task.progress.data.output_paths` 回报真实输出路径。Python、JSON Schema、Rust Host、Tauri Bridge 和前端状态层均只增加向后兼容的可选字段，Desktop IPC 继续使用 v1。

监控页只显示“已生成 N 个输出文件”和“打开输出目录”，不展示细粒度文件清单。打开时逐个核对已记录路径，优先使用首个仍存在的输出；较早路径失效时继续尝试其他可用路径。Windows 文件资源管理器由 Tauri Host 打开，不启动浏览器。

媒体执行失败时会明确回报 `media_status=failed`，避免部分失败被记成已完成；旧 Worker 或旧历史缺少 `output_paths` 时安全降级，不猜测完成状态。

## 5. 重新转录与继续转录

普通“重新转录”改为历史配置回填：

- 重新检查原输入；
- 恢复工作区、Preset、覆盖参数、字幕参数、模型、硬件和输出策略；
- 返回转录工作台顶部；
- 不加载模型、不创建任务、不自动执行；
- 一次性关机操作恢复为“无操作”。

取消或失败任务只有在同时具备可靠的已完成/已跳过输出清单和未完成媒体时才显示“继续转录”。续接会：

- 审计已完成/已跳过媒体的全部记录输出；
- 输出仍存在时排除该媒体；
- 输出已丢失、失败、等待中或取消时正在处理的媒体重新进入新任务；
- 冻结并沿用原任务输入、Preset、参数、模型、硬件和输出策略；
- 对剩余媒体重新执行原有冲突确认、覆盖或自动重命名规则；
- 不删除原历史，不恢复一次性关机操作；
- Worker 接受新任务后切换到性能监控顶部。

没有可靠完成清单或没有已完成媒体的异常任务仍使用“重新转录”，不会根据同名文件猜测。
