## 2. 多媒体整体进度

旧前端把 `transcription.running / postprocess.running / output.writing` 映射为整批任务的绝对区间。每个媒体都会重复这些阶段，因此第一个媒体写入输出达到高百分比后，第二个媒体重新进入转录阶段会导致整体进度回跳。

新增按任务隔离的前端进度跟踪器：

- 输入与模型准备占 0–10%；
- 全部媒体处理占 10–97%，按真实媒体总数等分；
- 单媒体份额内依次计入转录、后处理和写入；
- 稀疏事件沿用最近真实媒体百分比；
- 失败或跳过媒体结束当前媒体份额；
- 晚到的低百分比不得降低已确认值；
- 任务汇总为 99%，正式完成事件写入 100%；
- 完成、失败和取消后释放该任务跟踪状态。

任务监控和性能监控继续读取同一个 `TaskSnapshot.progress`，没有引入模拟 Worker 状态或修改 Desktop IPC v1。

“当前任务处理链路”改为在步骤达到边界时完成；任务完成或整体进度达到 100% 时，“任务汇总”显示勾选。

- 支持逐行路径；
- 支持 Explorer“复制为路径”的双引号格式；
- 支持同一行多个双引号路径；
- 保留含空格的文件名，不按空格拆分；
- 支持盘符路径和 UNC 路径；
- 剪贴板为空或不含可识别路径时不改动队列，并显示明确错误；
- 路径存在性和递归媒体检查继续交给正式 Host。

Desktop Bridge 新增 `readClipboardText()`，Tauri 只增加 `clipboard-manager:allow-read-text` 最小权限；Worker IPC 和协议 schema 未变化。

宽屏输入来源采用约 7:3 的纵向比例：添加本地媒体为主要区域，剪贴板为次要区域。窄窗口恢复自然高度。
