## 2. 方案与功能事实

- 原 `02 / TRANSCRIPTION PROFILE` 更名为“文本识别与参数”，仍只选择 TXT/Markdown 输出。
- 新增横跨工作台主内容区的 `03 / SRT SUBTITLE PROFILE`，标题为“SRT 字幕识别与参数”；原输出区顺延为 `04 / FILE OUTPUT`。
- 四张 SRT 预设卡分别映射到既有 `cn`、`cn2`、`en_v1`、`en_v2`。模型、语言、解码阈值和防幻觉语义继续来自正式 Preset，既有参数值没有被改写或复制出第二套事实源。
- TXT/Markdown 与 SRT 是明确的工作模式：选择 SRT 卡会冻结 SRT 输出和字幕参数；切回文本卡恢复文本输出。静态演示数据没有进入任务。
- SRT 使用 faster-whisper 已经返回的真实 segment `start`/`end` 时间戳，不重新推理、不估算整段音频时间，也不重写 faster-whisper、CTranslate2 或 CUDA 逻辑。
- 新字幕领域层负责短句合并、按行宽/行数/阅读速度拆分、时间轴不重叠、标准 `HH:MM:SS,mmm` 序号格式和 UTF-8 文件输出。
- 防幻觉预设仍使用正式后处理删除映射；被删除的识别句不会再次出现在 SRT 中。

## 3. 可调参数与自定义状态

正式 Worker 已允许安全覆盖的十项识别参数全部在文本和 SRT 模式中可调：

- `beam_size`、`best_of`、`patience`、`length_penalty`；
- `temperature`、`compression_ratio_threshold`、`log_prob_threshold`、`no_speech_threshold`；
- `condition_on_previous_text`、`min_silence_duration_ms`。

SRT 另提供六项排版参数：

- 每行最多字符 `max_characters_per_line`；
- 每条最多行数 `max_lines_per_cue`；
- 最短/最长显示时长 `min_cue_duration_ms`、`max_cue_duration_ms`；
- 最大阅读速度 `max_characters_per_second`；
- 字幕间隔 `cue_gap_ms`。

任一识别参数或 SRT 参数偏离当前预设后，UI 会明确显示“字幕自定义”，并把完整值冻结进任务草稿；“恢复 preset”可回到当前四套预设的正式值。范围验证同时存在于 React 状态、持久化迁移、Rust bridge、JSON Schema 和 Python IPC 边界。

## 5. 数据、IPC 与输出契约

Desktop IPC 仍为 v1。本次只增加可选字段：

- `output.srt`；
- `subtitle` 六项参数对象。

旧客户端不发送这些字段时行为不变，`schema_version` 没有升级。Rust bridge 和 Python Worker 均执行同一范围校验；SRT 模式要求字幕参数完整，文本任务继续沿用旧形状和旧输出行为。

输出目录遵循既有规则：SRT 写入 `SRT` 子目录；冲突重命名与 TXT/Markdown 使用相同策略。SRT-only 不产生兼容 TXT 备份，也不会把转录文本错误写入 `.srt`。桌面输出预览白名单增加 `.srt`，原 TXT/Markdown 预览不变。
