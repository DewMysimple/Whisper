记录性质：第四阶段发布产物辨识、清理和入口规则调整，不是 UI 代码修改，不占用“后续 UI 修改日志”的编号。下一次实际 UI 修改仍应创建 `第2次修改.md`。

## 1. 用户疑问

本次对话依次确认了以下问题：

1. `dist\release\WhisperSubtitle-portable\whisper-subtitle-desktop.exe` 与 `apps\desktop\src-tauri\target\release\whisper-subtitle-desktop.exe` 有什么区别。
2. 工程内散落了多少 `.exe`，其中哪些是真正的桌面应用入口。
3. 是否可以取消过期桌面版本，只保留一个实时更新的最新验收入口。
4. 清理过期便携 EXE 后是否仍有旧发布残余。
5. 旧发布产物清理后安装程序位于哪里。

## 2. 核查结论

清理前两个同名桌面 EXE 不是同一二进制：

| 位置 | 时间 | 大小 | SHA-256 | 结论 |
| --- | --- | ---: | --- | --- |
| `dist\release\WhisperSubtitle-portable\whisper-subtitle-desktop.exe` | 2026-07-17 00:53:48 | 9,774,080 | `B11DF5639ECC16C3CFC359A757A4CA9BAC7B5917108E0241216FBDBDE444477E` | 过期便携桌面版本 |
| `apps\desktop\src-tauri\target\release\whisper-subtitle-desktop.exe` | 2026-07-18 00:15:51 | 13,002,752 | `220253211ADDDC4D1B5D75A351BFE4F4D357A14375A84E8AE2016C24CDCDCF7F` | 第四阶段最新验收版本 |

正式发布脚本会先生成 `target\release` 中的 Tauri EXE，再把它复制到 `dist\release` 的便携目录。普通第四阶段 UI Release 构建只更新 `target\release`，不会自动重建完整发布目录，所以旧便携版没有同步第四阶段 UI。

旧便携目录的 `release-manifest.json` 所记录的 EXE 大小和 SHA-256 还与清理前的实际便携 EXE 不一致，因此该目录当时也不是一套清单验证通过的发布介质。

对整个工程进行包含 Git 忽略目录的只读扫描时共发现 239 个 `.exe`：绝大多数是 Rust 编译辅助文件、调试测试二进制、Python 虚拟环境工具和 TypeScript 编译器。真正需要用户关注的桌面入口只有最新验收 EXE和过期便携 EXE；安装包、Worker、CLI 和 Rust `deps` 文件不是第二个用户桌面入口。
