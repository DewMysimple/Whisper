本文仅记录将模型切换工作台中的“待自定义”占位卡替换为通义语音识别模型的设计结论。归档不代表已授权修改正式工程，不得据此自动下载模型、安装依赖、修改源码、重建 Worker 或更新正式二进制。

## 用户意图与已确定选择

用户希望第三张模型卡不再作为抽象的自定义模型入口，而是成为正式可用的通义本地语音识别模型。

讨论中已确定：

- 使用 `Qwen3-ASR-1.7B`；
- 配套 `Qwen3-ForcedAligner-0.6B`，保证 SRT 使用真实时间戳；
- 首版作为完整第三模型进入正式任务、历史、重试和输出链路；
- 支持 TXT、Markdown、SRT 与 SRT 伴随 TXT；
- 仅支持 NVIDIA CUDA，默认使用 BF16，FP16 仅作为能力回退；
- 通过 ModelScope 下载模型并完成真实 CUDA 验收；
- 软件运行时保持本地离线，不在本批引入软件内联网下载；
- 使用独立本地 Sidecar，避免将 PyTorch 与现有 faster-whisper/CTranslate2 放入同一进程；
- 选择通义后显示通义专属参数，不展示无法真实生效的 Whisper 参数；
- `large-v3-turbo` 继续作为默认模型，通义安装后也不会自动替换默认选择。

## 工程事实与主要风险

当前正式 Worker 以 faster-whisper 1.2.1 和 CTranslate2 4.8.1 为核心，生产冻结环境刻意排除了 `torch`、`torchaudio` 和 `torchvision`。Qwen3-ASR 使用 PyTorch/Transformers 或 vLLM，不能被当作一个普通 CTranslate2 模型目录直接加载。

正式接入的主要影响包括：

1. **运行时隔离**
   - Qwen3-ASR 需要独立 Python/PyTorch 推理栈。
   - 现有工程历史上已经发现 PyTorch、AV、NumPy 与 CUDA DLL 的导入顺序风险。
   - 合并到当前 Worker 会明显增加体积，并扩大 Whisper 稳定链路的兼容风险。

2. **模型体积**
   - ModelScope 上的 Qwen3-ASR-1.7B 约 4.70 GB。
   - ForcedAligner-0.6B 约 1.84 GB。
   - 两套权重合计约 6.5 GB，尚未计入 PyTorch、Transformers 和 Sidecar 依赖。

3. **参数不兼容**
   - Whisper 的 beam、温度回退、压缩率阈值、no-speech 阈值和 CTranslate2 精度选项不能原样用于 Qwen。
   - Qwen 提供语言提示、上下文/术语提示和贪心生成等自己的推理语义。
   - Qwen 不提供与 Whisper segment 完全对应的 log probability、压缩率和 no-speech 指标，正式 UI 不得模拟这些数据。

4. **字幕时间轴**
   - Qwen3-ASR 本体负责识别文字。
   - SRT 需要 Qwen3-ForcedAligner 提供真实字词时间边界。
   - 对齐器单次支持最长约 5 分钟语音，长媒体必须安全分块并合并时间偏移。

5. **Windows 冻结与显存**
   - 官方建议在隔离的 Python 3.12 环境中运行。
   - RTX 5070 Ti 16 GB 具备进行 1.7B + 对齐器 BF16 验证的基础条件，但正式能力仍须以本机实测为准。
   - 模型切换必须释放上一后端的显存，不能让 Whisper 与 Qwen 长期同时驻留。

## 暂存的完整实施草案

### 1. 模型库与本地文件

- 将第三张“待自定义”占位卡替换为 `Qwen3 ASR 1.7B`。
- 三列单行布局、当前主题、默认橙色及自定义强调色 Token 保持不变。
- 卡片分别显示 ASR 模型、时间对齐器、合计空间、CUDA/BF16 和加载状态。
- 只有 ASR 与对齐器均完整时才允许选择。
- 预期正式目录：
  - `models\qwen3-asr-1.7b`
  - `models\qwen3-forced-aligner-0.6b`
- 模型下载后生成来源、修订版本、文件大小及 SHA-256 清单；日常刷新只做低成本完整性检查。
- “打开模型目录”和“刷新模型”继续工作，不增加软件内下载按钮。

### 2. 独立通义推理 Sidecar

- 使用独立 Python 3.12 环境和 Transformers 后端。
- 候选依赖基线：
  - `qwen-asr==0.0.6`
  - `transformers==4.57.6`
  - 与本机 CUDA 12.8 和 RTX 5070 Ti 兼容的 Windows PyTorch
- 首版不采用 vLLM、Docker、FlashAttention、外部服务或 WebUI。
- 新增独立 Qwen Sidecar；现有主 Worker 继续负责：
  - 正式任务队列；
  - 输入检查；
  - 输出规划与冲突处理；
  - 历史、重试和继续转录；
  - TXT/Markdown/SRT 写入。
- 主 Worker 与 Sidecar 使用仅限本机进程间的 JSON Lines 协议，至少包含：
  - `load`
  - `transcribe`
  - `cancel`
  - `shutdown`
- Sidecar 只接受已校验的本地媒体和本地模型路径，不接受 URL。
- 切换到 Qwen 前释放 CTranslate2 模型；切回 Whisper 时退出 Sidecar 并释放 PyTorch 显存。
- Qwen 任务取消时终止当前推理、丢弃未完成结果，不写出半成品。
- Desktop、主 Worker 和窗口关闭链路必须清理 Sidecar 及其子进程。

### 3. Preset、参数与硬件

- 四个现有 Preset 身份继续保留：
  - `cn`、`cn2` 默认使用 Qwen 原生多语种检测，以保留中文主体中的英语；
  - `en_v1`、`en_v2` 强制英语识别；
  - `cn2`、`en_v2` 继续应用正式输出后处理，但不宣称使用了 Whisper 解码阈值。
- Qwen 不支持当前“翻译为英语”任务；前端状态、Rust Host、主 Worker 和 Sidecar 均应拒绝 Qwen 翻译任务。
- Qwen 专属参数区域仅提供真实有效能力：
  - 自动多语种／按 Preset 强制语言；
  - 上下文提示；
  - 术语提示；
  - 固定贪心解码和内部 Token 上限的只读说明。
- 上下文和术语继续执行长度、控制字符、空白和换行规范化；术语只用于识别提示，不强制插入或替换。
- Qwen 硬件配置独立保存：
  - 仅 CUDA；
  - GPU 设备索引；
  - BF16 推荐；
  - FP16 兼容回退。
- 选择 Qwen 时隐藏 CPU、CTranslate2 INT8、CPU 线程等无效设置；切回 V3/Turbo 后恢复原 Whisper 硬件配置。

### 4. 输出、历史与兼容性

- 将 Qwen 识别文字和 ForcedAligner 真实时间边界转换为统一的内部转录单元。
- 继续复用现有：
  - TXT/Markdown 智能排版；
  - SRT 单行字幕；
  - SRT 伴随 TXT；
  - 自定义根目录；
  - 同名覆盖、跳过和自动重命名；
  - 原子写入；
  - 任务续接。
- SRT 对齐失败时当前媒体失败，不生成比例推算或模拟时间戳。
- 任务历史、详情、重试确认框、性能监控和 Worker 日志显示真实模型和推理后端。
- Qwen 诊断显示真实检测语言、对齐单元、提示词状态和运行错误；不伪造 Whisper 置信指标。
- `large-v3`、`large-v3-turbo`、旧隐藏模型和旧历史继续兼容。

### 5. 内部接口草案

- `ModelId` 增加 `qwen3-asr-1.7b`。
- 增加模型后端标识、Qwen 参数档案和 Qwen CUDA 硬件快照。
- 任务草稿、队列事件、历史、重试和继续转录冻结真实后端参数。
- Desktop IPC v1 通过可选字段向后兼容扩展，不升级版本号。
- Qwen Sidecar 协议属于内部实现，不向前端开放任意进程或命令执行能力。

## 未来验收计划

重新授权后应至少设置以下检查点：

1. **CP0—基线保护**：记录 HEAD、脏工作区、保护文件、进程、模型和正式二进制哈希。
2. **CP1—运行可行性**：完成 ModelScope 下载、Python 3.12 隔离环境及本机 BF16 短音频识别。
3. **CP2—Sidecar**：验证加载、退出、异常、取消、进程清理及显存释放。
4. **CP3—正式任务链路**：验证模型冻结、V3/Qwen 混合队列、历史重试和继续转录。
5. **CP4—UI 与参数**：验证第三张模型卡、Qwen 专属参数、硬件界面和活动任务锁定。
6. **CP5—真实输出**：
   - 四个 Preset 的 TXT、Markdown 和 SRT；
   - SRT 与伴随 TXT 字节一致；
   - 超过 5 分钟媒体的分块时间轴严格递增；
   - 取消任务不产生半成品；
   - 提示词和术语不得导致未经语音支持的强制插入。
7. **CP6—复杂场景对照**：使用既有复杂中英媒体比较 Qwen、Large V3 和 Turbo，如实记录 CER、英语保留、术语命中、重复和耗时，不预设 Qwen 必然更好。
8. **CP7—完整回归**：Python、Rust、TypeScript、Vitest、ESLint、Prettier、生产构建和 Playwright。
9. 只更新正式 Desktop、主 Worker、新增 Qwen Sidecar 及必要依赖；不生成安装程序。
