## 已确认的结论

### 1. 当前转录核心不需要推倒重写

当前正式工程已经不是早期的四份重复脚本，而是以下分层链路：

```text
Preset 注册表
  → TranscriptionService
  → FasterWhisperEngine 适配器
  → faster-whisper / CTranslate2
  → 后处理策略
  → 输出存储
```

桌面侧还具备常驻 Worker、串行任务队列、模型复用、空闲释放、取消检查点、失败隔离与版本化 IPC。该结构应继续保留，不应因为早期代码由网页 AI 协助生成而整体推翻。

### 2. 基本模型调用方式符合官方示例

当前实现采用：

- `WhisperModel(model_path, device, compute_type, cpu_threads, num_workers)`；
- `model.transcribe(...)`；
- 完整迭代惰性的 `segments` 生成器；
- RTX GPU 使用 `float16`；
- CPU 回退使用 `int8`；
- 模型为 `large-v3-turbo`；
- 使用 Silero VAD；
- `beam_size=5`；
- 正式 Worker 固定 faster-whisper `1.2.1` 与 CTranslate2 `4.8.1`。

这些做法与官方 API 和示例一致。当前主要问题不是基础调用方式错误，而是尚未通过足够丰富的真实材料证明现有参数组合最优。

### 3. 现有质量验证材料不足

当前真实回归材料主要是：

- 约 5.3 秒的 Windows SAPI 中文合成语音；
- 约 8.7 秒的英文回归语音；
- golden output 一致性；
- RTX 5070 Ti 上的短音频 GPU Worker 验证。

这些材料可以证明链路可运行、输出未意外漂移、GPU 生效和模型可以复用，但不能充分评价真人口音、长视频、噪声、多人对话、中英混合、专有名词、长静音、漏句和尾部幻觉。

因此未来若开展优化，首先需要建立真实质量基线，而不是直接修改参数。

## “检测到语言概率”的确认结果

用户判断基本正确：当前显示效果等同于硬编码 `100%`，并不是真实语言检测结果。

四个 Preset 已经预先传入 `language="zh"` 或 `language="en"`。faster-whisper 在语言已指定时不会执行自动语言检测，并将 `language_probability` 返回为 `1`。正式应用随后将其显示成“检测到语言，概率 1.00”，因此文案具有误导性。

这里不是正式工程源码直接写死概率值，但实际语义与硬编码相同。

未来若整改，建议保留固定语言对稳定性的帮助，只调整状态表达：

```text
转录语言：中文
来源：Preset 指定
```

只有未来新增真正的自动语言识别模式时，才显示检测概率。当前未授权执行该整改。

## 讨论过的候选优化方向

以下内容均为候选设想，当前不执行。

### 解码质量

1. 评估将单一 `temperature=0.0` 与官方温度回退序列进行 A/B 测试；当前单一零温度不会在压缩率或平均概率不合格时尝试后续温度。
2. 明确 `best_of` 只在非零温度采样时生效；当前零温度下它是休眠参数，不应让用户误以为持续参与解码。
3. 对当前中英文 `initial_prompt` 做保留、精简、关闭和 `hotwords` 替代测试，防止 Prompt 诱导语法改写或不必要偏置。
4. 对 VAD 的 300ms、500ms、1000ms、2000ms 和关闭状态做真人材料比较，确认短停顿、漏词和尾部幻觉之间的取舍。

### 性能

1. 在不替换当前稳定模式的前提下，评估 `BatchedInferencePipeline` 的 batch 4 / batch 8 候选模式。
2. 对 RTX 5070 Ti 比较 `float16` 与 `int8_float16` 的速度、显存和质量，默认仍以 FP16 为保守基准。
3. CPU 回退当前固定 4 线程，未来可根据物理核心数进行基准后动态选择。
4. 保持 `num_workers=1` 与当前串行 Worker 队列一致；未经并发架构评估，不应盲目增加 Worker 数量。

### 可诊断性与工程质量

1. 可选采集 faster-whisper 已返回但当前未充分利用的 `avg_logprob`、`no_speech_prob`、`compression_ratio`、最终温度、原始时长与 VAD 后时长。
2. 评测时分别保留模型原始文本和正式后处理文本，用于区分模型错误与后处理错误；不静默增加正式用户输出文件。
3. 将全局 `warnings.filterwarnings("ignore")` 收窄为明确的已知警告，保留 CUDA、模型、参数弃用和音频解码诊断。
4. 对超长音频评估流式 Segment 合并，降低不必要的完整 Segment 列表驻留；任何实现必须保持输出完全一致。

### 已发现但不得顺手修改的历史行为

中文后处理仍保留一个历史兼容缺陷：ASCII 单引号会被替换成异常字符串。它可能影响中英混合、英文缩写和包含单引号的文本。该问题属于输出行为变更，必须单独批准、更新回归基线后才能修复，本轮不处理。

## 如果未来重新启动该工作

建议单独建立“转录核心质量评测与优化”工作阶段，而不是混入 UI 修改批次。推荐顺序：

1. 冻结当前参数与正式输出基线；
2. 建立真人中英文、噪声、长视频、多人、专名和长静音评测材料；
3. 记录 CER、WER、插入、删除、重复幻觉、实时倍率和显存峰值；
4. 在独立评测工具中逐项运行候选参数，不先改正式 Preset；
5. 形成对比报告；
6. 由用户明确批准具体候选后，再修改正式行为、测试与文档。

如果未来只执行第一步，建议范围限定为“诊断采集、质量评测框架与当前参数基线”，且不改变用户当前得到的转录文本。
