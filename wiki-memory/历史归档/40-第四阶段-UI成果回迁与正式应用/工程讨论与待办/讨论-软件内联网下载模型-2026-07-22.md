# 讨论：软件内联网下载模型

日期：2026-07-22。

状态：Deferred / Not Authorized（已讨论并明确暂缓，未实施）。

## 1. 讨论目标

评估在正式 WhisperSubtitle 的“模型切换”工作台中增加联网下载能力：用户点击缺失模型的下载按钮后，由软件自动从可信模型仓库下载、校验并安装到正式模型目录。

本记录只保存技术分析和未来实施边界，不代表实施授权，不得据此自动修改代码、Worker、Desktop IPC、网络权限、正式 EXE 或模型文件。

## 2. 当前事实

- 当前模型工作台只发现和加载本地模型，不执行联网下载。
- 正式模型目录为 `应用目录\models\<model-id>`。
- 当前支持 `tiny`、`base`、`small`、`medium`、`large-v3`、`large-v3-turbo` 六个多语言 CTranslate2 模型。
- 本地模型至少必须包含 `config.json` 和 `model.bin`，通常还包括 `tokenizer.json`、`vocabulary.json` 和 `preprocessor_config.json`。
- 正式 Worker 已包含 Hugging Face Hub 的运行元数据和 `hf_xet` 组件，但当前 Desktop IPC v1 没有下载命令、进度事件或取消语义。
- WebView 当前保持 `connect-src 'none'`，软件不允许前端直接访问外部网络。
- 手动下载和“打开模型目录／刷新模型”必须继续保留为后备方案。

参考资料：

- [Hugging Face：下载 Hub 文件](https://huggingface.co/docs/huggingface_hub/guides/download)
- [Hugging Face：文件下载接口](https://huggingface.co/docs/huggingface_hub/package_reference/file_download)
- [faster-whisper 官方工程](https://github.com/SYSTRAN/faster-whisper)

## 3. 路线比较

### 3.1 WebView 前端直接下载

需要开放 CSP、Tauri 网络权限并在前端处理 Hugging Face 重定向、Xet/LFS、大文件、取消及异常恢复。网络能力会暴露到 WebView，安全边界明显扩大。

结论：不推荐。

### 3.2 Rust Host 直接下载

可以保持网络能力在本地 Host，但需要新增 Rust Hugging Face 客户端，重新实现或接入仓库快照、缓存、断点续传、Xet、大文件校验和进度上报。会与 Worker 现有 Python/Hugging Face 依赖形成两套下载栈。

结论：可行，但重复建设较多。

### 3.3 Python Worker 专用下载线程

复用 `huggingface_hub.snapshot_download`、本地目录、缓存和 `hf_xet` 分块下载能力；WebView 继续禁止联网。下载不能占用当前 Worker 命令线程，否则长时间下载会阻塞健康检查、性能轮询和取消命令，因此必须使用独立下载线程和独立状态机。

结论：未来实施时的推荐路线。

## 4. 推荐的未来流程

```text
点击下载模型
→ 查询固定仓库 revision 和实际缺失容量
→ 检查模型目录与磁盘空间
→ 主题化确认框显示来源、大小和目标目录
→ 下载到同一磁盘的 .partial 临时目录
→ 持续上报容量、百分比、速度和阶段
→ 用户可取消，缓存和安全临时数据保留供重试
→ 校验必需文件、仓库 revision 和模型可加载性
→ 原子改名为 models\<model-id>
→ 自动刷新模型工作台
→ 用户选择是否立即设为转录模型
```

网络和文件系统规则：

- 只允许软件内置白名单中的六个模型及固定仓库，不接受任意 URL、仓库名或输出路径。
- 仓库应固定到明确的 revision，避免远端 `main` 变化造成不可复现安装。
- 使用 Hugging Face `dry_run` 获取需要下载的文件和容量，再进行磁盘空间预检。
- 未完成内容只能存在于 `.partial` 或专用缓存目录，不能被当前模型发现逻辑误判为已安装。
- 正式目录迁移必须在同一卷内完成，避免复制大模型时产生第二份完整占用。
- 下载失败、断网、代理、Hugging Face 不可访问和磁盘不足必须提供可操作错误，不产生模拟成功。
- 软件关闭时不得留下“已安装”假状态；再次启动应识别可恢复下载。
- 手动安装入口永久保留，第一版不引入第三方镜像。

## 5. 推荐的第一版范围

如果未来获得一次明确授权，建议首版只包含：

- 缺失模型卡上的“下载模型”；
- 同一时间只允许一个下载任务；
- 下载前容量、来源和目标路径确认；
- 下载百分比、已下载／总容量、速度和当前阶段；
- 取消、失败重试和基于缓存的继续下载；
- 下载完成后的文件校验、真实 `model.load` 校验和自动刷新；
- 软件关闭／重启后的安全恢复；
- 下载完成系统通知；
- `tiny` 用于快速端到端测试，`large-v3` 用于真实大文件、取消和恢复验收。

第一版不包含：

- 暂停按钮（取消后重试利用缓存即可）；
- 删除已安装模型；
- 任意第三方模型、仓库输入或镜像地址；
- Hugging Face 账号登录、私有模型或 Token 管理；
- 多模型并行下载；
- 修改模型推理、Preset、字幕、文本排版或输出行为。

## 6. 预计改动面

未来实施会涉及：

- 模型工作台的下载、进度、取消和错误 UI；
- 新增下载状态持久化或可恢复临时状态；
- Desktop Bridge 下载接口；
- Desktop IPC v1 的向后兼容可选命令／事件扩展；
- Worker 独立下载线程、白名单、revision、磁盘预检、校验与取消；
- PyInstaller 对 `huggingface_hub`、`hf_xet` 和相关动态依赖的显式冻结验证；
- 断网、磁盘不足、取消、崩溃恢复、重复点击、模型已经存在和大文件真实下载测试；
- 正式 Worker 与 Desktop EXE 重新构建。

复杂度为中等。难点主要是大文件生命周期、可靠取消／恢复、磁盘安全和冻结 Worker 依赖，而不是按钮本身。合理约束在上述第一版范围内，可以作为一次独立的“第 21 次修改”连续执行；未获得用户新授权前不得开始。

## 7. 当前决定

用户决定暂不实施软件内联网下载模型。

当前软件继续保持：

- 只使用本地模型；
- 用户自行从可信来源下载 CTranslate2 模型；
- 通过“打开模型目录”放置模型；
- 通过“刷新模型”重新检查安装状态；
- WebView 不联网；
- 不修改当前 Worker、Desktop IPC v1 和正式二进制。
