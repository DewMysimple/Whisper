# 报错处理 002：SRT 字幕超出行容量

日期：2026-07-19。  
状态：已修复、已完成全量回归、已重新冻结并替换正式 Worker、已启动正式桌面软件。

## 1. 用户可见现象

报错处理 001 关闭 Tauri 字段命名问题后，正式任务能够进入 Worker，也会创建 `SRT` 文件夹，但最终没有生成 `.srt` 文件。Worker 日志记录：

```text
ValueError: subtitle cue exceeds configured line capacity
```

调用链：

```text
worker/runtime.py::_execute_task
application/transcribe.py::transcribe_file
domain/subtitles.py::build_srt_document
domain/subtitles.py::build_subtitle_cues
domain/subtitles.py::_wrap_text
```

实际媒体为：

```text
C:\Users\Administrator\Desktop\Bilibili\英语兔\全网最适合中国人的免费音标课(纯干货, 超详细!)\P2-主要音标体系.mp4
```

用户选择中文转录 SRT，默认布局为每行最多 18 字符、每条最多 2 行。

## 2. 根因

旧排版流程先把 `18 × 2` 简化为“总容量 36 字符”，按 36 字符切分句子；随后再按每行 18 字符执行尊重英文空格和单词边界的换行。

总字符数不超过 36 并不保证实际只产生两行。例如以下 31 字符文本：

```text
This is a sentence with several
```

按英文空格换行后会得到：

```text
This is a
sentence with
several
```

旧代码发现三行后直接抛出异常，没有把第三行继续放入下一条字幕。因此转录和后处理已经执行，但 SRT 文档尚未成功构造，最终写入函数没有运行。

`SRT` 文件夹提前存在，是因为输出目录在推理和字幕文档构造之前准备；不能把文件夹创建等同于 SRT 文件已经写入。

该问题在中文行宽处理英文课程时更容易触发，但本质是通用 SRT 排版缺陷，不应通过要求用户更换 Preset 或手动增大参数规避。

## 3. 修复设计

文件：`src/whisper_subtitle/domain/subtitles.py`

排版过程不再先用“每行字符数 × 最大行数”估算总容量，也不再在超过估算后抛错。新流程为：

1. 直接按真实单行宽度拆分文本，优先保留英文单词边界和标点边界；
2. 单个单词超过行宽时安全硬拆分，不截断文字；
3. 按 `max_lines_per_cue` 把实际行分组为多条字幕；
4. 同时遵守由 `max_characters_per_second × max_cue_duration_ms` 得到的阅读字符预算；
5. 按每组字幕的实际字符权重重新分配原始句子的时间范围；
6. 保留原始首个开始时间和最终结束时间，继续执行既有字幕间隔与非重叠规则。

内部待写入对象现在直接携带已经验证的字幕行，不再在最后一步重新换行并产生第二套不一致结果。

## 4. 回归门禁

文件：`tests/test_subtitles.py`

新增两项确定性回归：

- 英文单词边界导致实际超过两行时，自动生成下一条字幕；断言文字不丢失、每条最多两行、每行不超过用户宽度、原始起止时间保留；
- 单个超长英文 token 无法在空格处拆分时执行安全硬拆分；断言内容不截断、行数和行宽合法、时间范围保留。

既有长英文句子、中文合并、防幻觉去重、时间戳和应用写入测试继续通过。
