# 报错处理 009：系统通知点击无法返回软件

日期：2026-07-25  
状态：已修复代码并更新正式 Desktop；等待用户在下一次真实通知中点击复验。

## 现象

WhisperSubtitle 已能使用自有 Windows 通知身份和蜘蛛侠图标发送任务终态通知，但点击通知只会让 Toast 消失，主程序不会恢复或获得焦点。通知正文还显示任务名称，占用了用户更关心的总体耗时位置。

## 根因

`tauri-winrt-notification` 创建的 Toast 只配置了标题、两行文本、图标和静音标记，没有注册 `on_activated` 回调，也没有通知操作按钮。因此 Windows 完成了通知关闭动作，但应用没有收到恢复主窗口的行为。

前端同时在 `show_app_notification` 之后再次调用 `play_notification_sound`，而 Rust 命令本身也会播放声音，存在同一通知请求两次声音的风险。

## 修复

- 原生 Toast 改为长通知；
- 增加“返回 WhisperSubtitle”按钮；
- 正文点击和按钮点击共用激活回调；
- 回调获取 Tauri 主窗口并依次调用显示、取消最小化和聚焦；
- 保持 WhisperSubtitle AppUserModelID 和蜘蛛侠圆形 Logo；
- 普通终态第一行改为“总耗时 MM:SS”，不再传递任务名称；
- 声音统一由原生命令执行一次，前端不再重复调用；
- 通知或聚焦失败与任务状态、输出写入和关机倒计时隔离。

## 回归

- 通知内容与调用次数 Vitest通过；
- Windows通知状态映射及Rust全量测试通过；
- TypeScript、ESLint、生产构建和正式 Tauri Release构建通过；
- 正式 EXE启动后可拉起 Worker，关闭主窗口后无残留进程；
- 当前环境没有可用的 Windows通知点击自动化驱动，因此不伪造“真实点击已自动完成”；由用户在下一次真实通知中完成最终可见复验。
