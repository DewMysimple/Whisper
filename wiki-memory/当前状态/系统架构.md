# 系统架构

## 分层关系

```text
React/TypeScript WebView
        ↓ typed DesktopBridge
Tauri 2 / Rust Host
        ↓ validated stdin/stdout JSONL
常驻 Python Worker
        ↓
application → domain → infrastructure
```

- `domain/` 保存契约、Preset、转录接口、后处理和字幕布局规则。
- `application/` 编排单文件或批量转录。
- `infrastructure/` 负责 faster-whisper、CUDA、硬件、媒体发现、性能和输出文件。
- `worker/` 负责常驻进程、串行任务、取消、模型缓存和 IPC 适配。
- Tauri Host 是 WebView 与 Worker 的唯一运行时边界，负责权限、生命周期、协议校验和受限文件预览。

## 当前内部职责边界

- Web `workspace.ts` 保留状态与动作组合；事件归并位于 `state/workspaceEvents.ts`，任务状态纯函数位于 `state/workspaceTaskState.ts`，草稿/持久化/外观/性能纯逻辑分别位于 `workspaceDraft.ts`、`workspacePersistence.ts`、`appearancePreferences.ts`、`performanceMetrics.ts`。
- `tauriDesktopBridge.ts` 保留 Tauri 调用、订阅、轮询与生命周期；Worker 消息字段解码位于 `bridge/tauriWorkerDecoder.ts`，事件到任务状态的归并位于 `bridge/tauriWorkerEvents.ts`。
- `application/transcribe.py` 保留转录流程编排；混合语言/中文细节复核位于 `application/recognition_passes.py`。
- `worker/runtime.py` 保留常驻 Worker 生命周期；共享运行时类型位于 `worker/runtime_types.py`，模型缓存和任务数据分别位于 `worker/model_cache.py`、`worker/task.py`。
- Rust `worker_host.rs` 保留进程监管与命令发送；模型、媒体、日志和启动参数校验分别位于 `worker_host/models.rs`、`worker_host/media.rs`、`worker_host/logs.rs`、`worker_host/validation.rs`。
- Python `protocol/desktop_ipc.py` 保留协议对象与生命周期；通用字段/事件校验和质量诊断校验分别位于 `desktop_ipc_validation.py`、`desktop_ipc_quality.py`。Rust 对应的质量诊断校验位于 `protocol_quality.rs`，两端共享 schema 约束但不互相调用。
- Python `worker/runtime.py` 保留常驻生命周期与队列分发；单任务执行位于 `worker/task_execution.py`，模型缓存和共享运行时类型继续独立维护。

这些模块拆分不构成新的运行时层，也不改变已有公开入口；后续功能修改应优先落在对应职责文件中。

## 数据流

`CLI 或 Desktop IPC → TranscriptionRequest → preset → 媒体发现 → 硬件/模型 → 转录 → 后处理 → 原子输出 → 进度与结果事件`。

Worker 通过单 dispatcher 串行执行任务，按任务冻结模型、Preset、硬件和输出计划；模型可以在任务之间复用，并在空闲超时后释放。

## 关键边界

- `contracts/desktop_ipc/v1/desktop_ipc.schema.json` 是跨语言协议事实来源。
- Worker stdout 只输出协议，普通日志写 stderr/日志通道。
- `apps/web` 不直接启动进程、执行 shell 或访问 Python；组件只依赖 typed `DesktopBridge`。
- Rust 不实现转录算法、Preset 或后处理。
- 默认输出写入媒体旁的 `Text`、`Markdown`、`SRT` 目录；自定义输出目录有独立覆盖/跳过规则。
