# 项目概览

## 项目目标

WhisperSubtitle 是面向 Windows 11 x64、NVIDIA GPU 和本地离线使用的字幕转录桌面应用。它提供统一 Python CLI、常驻 Worker、Tauri 2 + React/TypeScript 桌面界面，以及 TXT、Markdown、SRT 输出。

## 当前产品入口

- 完整便携版入口：`dist/WhisperSubtitle/WhisperSubtitle.exe`
- 完整便携版压缩包：`dist/WhisperSubtitle.zip`
- 开发编译产物：`apps/desktop/src-tauri/target/release/whisper-subtitle-desktop.exe`，不能脱离 Worker/模型作为最终交付物
- CLI：`python -m whisper_subtitle transcribe`、`check`、`worker`
- 正式桌面不打开浏览器、不启动 localhost 服务。

## 当前工作状态

截至 2026-09-18，正式桌面已移除模型切换、推理参数和硬件优化工作台，以及人工设备/精度偏好。Worker 在任务开始时自动选择硬件，任务仍记录实际模型与硬件；`model.load`、`model.unload` 仅作为 Desktop IPC v1 冻结 Worker 兼容命令保留，不由当前 UI 调用。

UI 开发期通过固定的 `http://127.0.0.1:1420` Vite/HMR 服务迭代；`corepack pnpm desktop:dev` 会自动启动该服务并连接真实 Tauri bridge。正式构建仍嵌入 `apps/web/dist/`，不启动 localhost。

转录工作台的启动卡片现为一体化“执行前清单”：任务开始前集中核对版本、模型、媒体数量与时长、输出和执行策略。清单与“文本识别模式”的 2×2 内卡片共用行高和行距；四张清单卡片是无选中态、无页面滚动副作用的配置快捷入口。“当前输出”“选择以启用”和执行前清单徽标共用高度与图文中心线，文本模式未启用继续使用文件图标，SRT 未启用继续使用字幕图标，“待补充”继续使用警告图标；待补充徽标、需要补充的清单卡片和 SRT“选择以启用”使用同一柔和强调色通道，当前输出仍保留绿色。“查看媒体文件进度”直接进入任务监控的逐文件进度；开发服务器通过非持久化 Mock 预览实时反映当前输入，没有新输入时继续显示上一轮监控任务，正式 Tauri/Worker 状态不受影响。

文件输出按保存位置、文件格式、写入规则和完成动作分为四张单列宽内卡片，避免右侧窄栏中的文本和控件被压缩；输出格式、冲突策略、媒体旁副本及完成动作的既有功能语义保持不变。

“任务监控与记录”工作台使用分层实时监控卡和本机历史卡片归档。实时监控将整体进度、当前媒体、输入来源和输出结果分组展示，并统一标题、状态、元信息与处理链路的响应式字阶；任务阶段显示“转录中”，旧历史中的 GPU 阶段措辞会在展示层归一化。历史记录在全屏桌面布局下固定为四列卡片，并按 3／2／1 列响应中小窗口。顶部四张概览卡是连续无间隙的唯一状态筛选入口，其中“需要处理”只显示失败任务；概览和历史管理面板共用一个外壳，不再形成两个悬浮区。搜索、放大后的日期日历、“清除历史”和“清除异常”位于同一自适应工具行。历史卡长名称在末尾显示省略号并保留完整悬停标题；右上角只显示与状态对齐的百分比，不使用进度条；“当前阶段”统一显示转录版本、执行阶段和输出格式，不再把已退役的识别策略当作版本特性展示。

Worker 日志工作台使用四张运行概览卡和统一诊断控制台，空会话会说明 Worker 启动、模型加载和任务执行三个采集阶段；有效日志按行号、日期/时间、来源和正文分列展示，复制与导出仍读取原始缓冲区。控制台在浅色主题下使用浅色诊断表面，在深色主题下使用深色表面，新配置的默认日志字号为 13px。偏好设置分别持久化桌面框架字号、工作台内容字号、Worker 日志字号、展开导航宽度和工作台最大宽度；框架与内容字号不再共用同一个缩放变量，旧版本 1 配置会迁移到新的分层字段。主题卡只保留预览和名称；展开导航宽度可以在侧栏边界直接拖拽，导航、工作台宽度及三组字号均可在设置页输入精确整数。两类数值使用协调的等宽字形，并比对应说明字阶高 2px；工作区尺寸值按右侧单位之前的白色数值区居中，三组字号值按各自数值框居中，宽度值保留强调色。`px` 固定在右侧独立单元，焦点仅绘制完整控件外框，不显示原生数字控件或内部假边框。
