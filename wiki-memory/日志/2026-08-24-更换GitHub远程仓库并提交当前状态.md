# 更换 GitHub 远程仓库并提交当前状态

## 目标

将本地仓库的 `origin` 更换为 `https://github.com/DewMysimple/Whisper.git`，审查当前工作树后提交适合进入远程仓库的工程状态并推送。

## 已确认的决策

- 新远程仓库可访问且当前没有分支引用；本地 `master` 作为首次推送分支。
- 当前 UI 改动作为工程快照提交，但没有宣称完成正式 UI 封版；Tauri Release 构建和 EXE 验收仍属于后续工作。
- 模型、虚拟环境、`node_modules`、Rust `target`、构建/发布产物、benchmark 临时运行目录和 `.workbuddy` 用户工作区不进入提交。

## 检查与操作

- 审查 `git status`、`.gitignore`、仓库资料策略、源码/测试/文档差异和本地大文件范围。
- 将旧 `Log/` 迁移产生的删除与 `wiki-memory/` 当前记忆及历史归档作为同一仓库卫生变更处理，保留审计资料，不删除生产代码、模型或用户工作区。
- 将 `origin` 的 fetch/push 地址改为新仓库。

## 文件变更

- 纳入当前 React/TypeScript UI、对应测试、README、docs、benchmark 基准路径更新和根目录 `AGENTS.md`。
- 纳入 `wiki-memory/` 当前状态、决策、知识、日志和 `历史归档/`；移除旧 `Log/` 路径，保留其历史内容在新归档位置。
- 不纳入被忽略的本地依赖、模型、缓存、构建产物、发布签名材料、临时 benchmark 运行结果和 `.workbuddy`。

## 测试与验证

- `whisper_env\\Scripts\\python.exe -m pytest -q`：352 passed。
- `corepack pnpm check`：格式检查、Lint、TypeScript 类型检查和 87 个前端测试全部通过。
- 全局 Python 直接运行 `python -m pytest -q` 因未激活项目环境而失败；该结果不代表代码失败，已用项目虚拟环境复验通过。
- 记忆体检在补齐日志索引后应再次运行并保持无孤儿页/断链。

## 待确认长期记忆

- 当前提交是可追溯的工程快照，不等于 UI 正式发布验收。
