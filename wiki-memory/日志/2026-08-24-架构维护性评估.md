# WhisperSubtitle 架构维护性评估

## 目标

从维护、功能修改管理和 UI 组织三个角度评估当前架构是否适合继续演进，不执行代码重构。

## 已确认的判断

- Tauri 2 + React/TypeScript + Rust Host + 常驻 Python Worker 的宏观分层正确，适合本地离线桌面应用。
- Python 的 domain/application/infrastructure 分层、CLI 与 Worker 共用 `TranscriptionService`、Rust 作为唯一桌面进程边界，都是可保留的基础。
- 当前主要问题不是层次错误，而是边界内部出现大文件、大状态中心和多份事实源，导致修改影响面偏大。
- UI 的 React 组件拆分、`DesktopBridge` 抽象、mock bridge 和 E2E 路径是正确方向；`workspace.ts` 与 `tauriDesktopBridge.ts` 继续集中职责会降低后续维护性。

## 检查与操作

- 检查 `docs/architecture/current_architecture.md`、`contracts/desktop_ipc/v1/desktop_ipc.schema.json`、Python Worker、Rust Host、React 状态与 bridge 实现。
- 记录了主要集中点：`apps/web/src/state/workspace.ts`、`apps/web/src/bridge/tauriDesktopBridge.ts`、`apps/desktop/src-tauri/src/worker_host.rs`、`src/whisper_subtitle/worker/runtime.py`、`src/whisper_subtitle/application/transcribe.py`。
- 对比了 Python `domain/presets.py` 与 Web `data/presets.ts`、`data/subtitlePresets.ts`，确认存在跨语言重复维护的预设与模型校准逻辑。
- 检查了 IPC 契约测试：schema 与 Python 枚举有一致性断言，但当前未发现跨语言类型/协议的自动生成链。

## 文件变更

- 仅新增本评估日志和日志索引；未修改 Python、Rust、React、测试或发布行为。

## 测试与验证

- 本轮为静态架构评估，未重新执行构建、完整测试或 Tauri 运行验证。
- 现有架构测试、协议测试和 UI 测试作为评估依据；其环境限制已记录在项目记忆重建日志中。

## 待确认长期记忆

- 是否批准按“先统一事实源，再拆大模块，最后整理 CSS”顺序进行渐进式维护性重构。
- 是否把预设目录、IPC fixtures 和功能影响矩阵纳入下一阶段正式维护规则。

## 问题、结果与下一步

- 结果：架构方向用对了，但当前维护性处于“可继续开发、需要控制债务”的状态；不建议推倒重来。
- 遗留问题：跨 Python/TypeScript/Rust 的契约和预设重复定义仍可能产生漂移。
- 下一步：如获授权，优先建立单一预设事实源或生成机制，并将 UI store、Tauri bridge、Rust Worker Host、Python Worker runtime 按职责拆成可独立测试的模块。
