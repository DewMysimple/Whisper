# 建立修改后提交推送约定

## 目标

用户确认上一轮转录工作台间距修改尚未提交或推送，并要求将“每次修改后都要提交并推送”设为硬性项目约定。

## 结论

今后每完成一次仓库修改任务并通过对应验证，必须创建独立 Git 提交并推送到当前分支的远程；未完成提交和推送，不得宣称任务完成。推送失败时必须如实报告原因，保留本地提交，不使用强推或历史改写。

## 变更

- 根目录 `AGENTS.md` 增加 Agent 执行层面的硬性提交与推送要求。
- `wiki-memory/当前状态/当前约束.md` 增加项目级提交、推送和范围隔离约束。
- `wiki-memory/知识/流程/开发与验证.md` 增加修改后的提交与推送流程。
- 本次一并提交上一轮转录工作台间距修改及其记忆日志。

## 验证

- 已核对当前分支为 `master`，远程为 `origin`，指向项目 GitHub 仓库。
- 提交前检查工作树，确认待提交变更均属于本次间距修复、记忆同步和提交推送约定。
- `python wiki-memory/工具/memory_lint.py check`：通过（35 个 Markdown 页面）。

## 遗留问题

- 无。提交与推送结果以本任务结束时的 Git 状态和远程核对为准。
