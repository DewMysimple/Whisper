# 优化仓库与发布目录结构

## 目标

参考 ObManage 的“同名成品目录 + 同名 ZIP”交付方式，降低 WhisperSubtitle 完整版入口层级，同时审计仓库顶层目录、发布中间态和最终运行时目录，保持现有产品架构与功能契约不变。

## 实际变更

- 最终便携版收敛为 `dist/WhisperSubtitle/` 与 `dist/WhisperSubtitle.zip`；友好入口为 `WhisperSubtitle.exe`，不再把 Cargo `target/release` 当作用户交付路径。
- 成品根目录只保留 EXE 和中文使用说明；Worker、CUDA 用户态依赖、直接模型、SBOM 与发布清单统一进入 `_internal/`。
- 标准 `release:build` 只生成完整便携目录、ZIP 和 SHA-256；可选 NSIS 介质改由 `release:build:installer` 显式生成并隔离在 `dist/installer/`。
- Rust Host 优先解析 `_internal/worker` 与 `_internal/models`，同时保留旧根级 `worker/models` 的兼容回退。
- 原 `packaging/` 与 `scripts/` 收口为 `tools/release/`、`tools/codegen/`、`tools/maintenance/`；`build/release/` 只保存可再生中间态，`dist/` 只保存可交付产物。
- 删除了与 Python/Tauri 实际资源逐字节重复的根级 `assets/logo.png`、`assets/logo.ico`；正式图标继续由各消费模块自己的资源目录提供。
- 发布脚本保持纯 ASCII，以兼容 Windows PowerShell 5；成品中文说明文件名在运行时由 Unicode 码点生成。首次真实装配发现并修复了 PowerShell 按系统代码页误读中文源文件名的问题。
- 可选 NSIS 初次验证还发现 Tauri bundler 会在 `offlineInstaller` 模式下对微软短链接发起 HEAD 请求，当前网络代理返回提前 EOF。安装器流程因此改为解析并校验本地微软签名的 WebView2 x64 离线安装器，将其作为安装介质 `_internal/distribution/` 的一部分交给 NSIS 钩子执行，打包阶段不再访问该短链接。

## 保持不变

- `apps/`、`src/`、`contracts/`、`tests/`、`docs/` 和 `wiki-memory/` 的责任边界清晰，未因目录美化进行无收益拆分。
- Desktop IPC v1、UI、Preset、转录、输出和硬件自动选择行为未改变。
- 本地模型、`whisper_env/`、既有非发布 `build/` 历史资料、Rust `target/` 和机器快捷方式均保留；发布脚本只替换自己拥有的 `build/release/` 与指定 `dist/` 产物。

## 验证

- `corepack pnpm check`：通过，Web 20 个测试文件、82 项测试通过。
- `./whisper_env/Scripts/python.exe -m pytest -q`：360 项通过。
- Rust `cargo fmt --check`、`cargo test --locked`、严格 Clippy：通过，34 项通过、2 项忽略。
- `corepack pnpm e2e`：12 项通过。
- `corepack pnpm release:build` 从全新 `build/release/` 中间态完整执行并以 0 退出；Worker 冻结、Tauri Release 编译、成品目录、ZIP 与校验文件均由标准命令生成。
- 可选安装器在改用本地微软签名 WebView2 离线安装器后通过真实 `makensis` 构建，生成 `dist/installer/WhisperSubtitle-Setup.exe`；打包日志不再访问微软短链接。
- 成品目录包含 931 个文件；manifest 覆盖除自身外的 930 个文件。磁盘文件、ZIP 内文件和 manifest SHA-256 逐项一致，外层 3 个关键 SHA-256 也一致。
- 从 `dist/WhisperSubtitle/WhisperSubtitle.exe` 启动 36 秒后，桌面与 `_internal/worker/whisper-subtitle-worker.exe` 均持续存活并越过 Host ready 超时门槛；关闭后没有遗留进程。

## 结论

正式完整版的用户入口已经从深层编译目录迁移到仓库根下的浅层 `dist` 目录。后续不得把 `target/release` 的单个 EXE 当作完整发布物，也不得把 Worker、模型或运行时依赖重新暴露到成品根目录。
