# 修复桌面 IPC 启动失败

## 故障

删除硬件优化工作台后，正式开发入口显示 `LOCAL IPC · FAILED`，并报告 `methods contains unsupported or duplicate values`；部分操作又把结构化 Tauri 错误显示成 `[object Object]`，桌面无法进入 Worker ready 状态。

## 根因

- 上一轮把 `model.load`、`model.unload` 误判为可直接删除的冗余命令，同时从 Rust Host 的 Desktop IPC v1 严格白名单移除。
- `apps/desktop/src-tauri/target/release/worker/` 中仍是 2026-07-26 的冻结 Worker，它按既有 v1 契约在 `worker.ready.capabilities.methods` 中声明这两个命令。
- 新 Host 因白名单收窄而拒绝第一条握手消息。既有“EXE 存活 5 秒”烟测只验证窗口进程没有退出，没有确认 Worker 子进程持续运行或 Host 已 ready，因此漏检。
- Web 的通用 `errorMessage` 对非 `Error` 对象直接调用 `String`，导致 Tauri 的结构化错误变成 `[object Object]`。

## 修复

- 恢复 `model.load`、`model.unload` 作为 Desktop IPC v1 兼容命令，并恢复 Python Worker 的加载/卸载处理；它们不恢复桌面 UI，也不恢复人工硬件偏好。
- `model.load` 仅接受可选 `model_id`，硬件字段继续由跨语言协议校验明确拒绝；实际硬件仍自动解析。
- 增加 Rust 回归测试，固定验证现有冻结 Worker 的完整 `worker.ready` 能力列表，防止再次收窄 v1 白名单。
- 增加 Python 协议与运行时回归，覆盖兼容命令、自动硬件加载、活动任务期间拒绝卸载，以及硬件偏好不回归。
- 修复 Web 结构化错误消息提取，并增加 `[object Object]` 回归测试。
- 将桌面烟测门禁提升为：必须确认桌面进程和受控 Worker 子进程同时存活，不能只检查窗口进程。

## 验证

- 使用故障现场同一份 2026-07-26 冻结 Worker 启动新 Release Host：桌面与唯一 Worker 子进程持续运行 7 秒，`IPC_HANDSHAKE_COMPATIBILITY=PASS`。
- `corepack pnpm check`：Web 20 files、82 tests passed，仓库卫生、格式、lint、typecheck、模型/Preset 投影与记忆门禁通过。
- `whisper_env\\Scripts\\python.exe -m pytest -q`：357 passed。
- Rust：`cargo fmt --check`、`cargo test --locked`（33 passed、2 ignored）和 clippy 严格检查通过。
- Playwright：12 passed；`corepack pnpm desktop:build` 通过。
- 既有 JavaScript chunk size 与 MSVC linker 信息性警告不构成本次阻塞。

## 当前边界

- 模型切换、推理参数和硬件优化工作台仍保持退役；Web/Tauri bridge 不调用兼容模型命令。
- 人工设备、计算精度、CPU 线程字段仍已删除，旧偏好继续在迁移时丢弃。
- `model.load`、`model.unload` 不能再按“无 UI 调用方”直接删除；若未来升级协议，只能通过新版本和冻结 Worker 兼容验收处理。
