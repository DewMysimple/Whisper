# 启用 Vite 开发服务器并审计 Apps 目录

## 目标

为频繁 UI 修改建立 localhost Vite/HMR 开发循环，同时评估 `apps/` 下的 Web 与 Desktop 目录是否需要重新组织，并把旧的“开发期也不使用开发服务器”描述收敛为只约束正式 Release。

## 实际变更

- `apps/web` 新增标准 `dev` 与 `preview` 脚本；根工作区新增 `web:dev`，从 `apps/web` 运行 `npm run dev` 可以直接启动 Vite，根目录 `npm run dev` 则作为完整 Tauri 开发模式的快捷入口。
- Vite 固定只监听 `127.0.0.1:1420` 并启用 HMR，端口占用时直接失败，避免静默切换到与 Tauri `devUrl` 不一致的端口。
- Tauri `beforeDevCommand` 自动启动 Web 工作区的 Vite 服务，`desktop:dev` 不再先做一次完整静态构建。
- `frontendDist=../../web/dist` 保持不变；`tauri build`、发布脚本和最终 EXE 继续使用静态资源，不把 Node、Vite 或 localhost 带入正式运行时。
- README、架构文档、仓库策略、开发指南和 active 记忆统一改为：开发期允许固定 loopback Vite/HMR，正式产品仍禁止依赖 localhost 或浏览器入口。

## Apps 目录评估

- `apps/web` 与 `apps/desktop` 是明确的运行时责任边界：前者拥有 React UI、状态和 typed bridge，后者拥有 Tauri/Rust Host、权限、Worker 监管与 Windows 集成。
- `apps/desktop/src-tauri` 是 Tauri 标准工程结构；把它上移、改名或与 Web 合并会增加工具配置和路径迁移成本，没有架构收益。
- Web 的 `components/`、`state/`、`bridge/`、`contracts/`、`data/`、`assets/` 与测试边界仍可辨识；Desktop 的 Rust 子模块也按 Host 职责拆分，不需要为了目录层级继续碎片化。
- `web/dist`、测试结果、各级 `node_modules`、`src-tauri/target` 与 `src-tauri/gen` 都是已忽略的可再生目录。它们会让本地文件树看起来较多，但不属于源码混乱；本期在 `apps/README.md` 明确标注来源和保留策略，不删除用户本地缓存。
- 全局 `styles.css` 的级联顺序包含多个历史 UI 调整；仅按行数机械拆分会增加视觉回归风险。后续真实 UI 修改可按稳定的功能边界逐步收口，但本期不做无行为收益的搬迁。

## 验证

- `npm run dev`（从 `apps/web`）和 `corepack pnpm web:dev`：Vite 在 `127.0.0.1:1420` 启动；首页和 `/@vite/client` 均返回 200，浏览器实际建立 `ws://127.0.0.1:1420` HMR WebSocket。
- `corepack pnpm desktop:dev`：Tauri 自动运行 `beforeDevCommand`，开发桌面、Vite 和受控 Python Worker 同时存活；退出后端口与进程均清理。
- `corepack pnpm desktop:build`：通过，Release 构建未启动开发服务器。
- `corepack pnpm release:build`：通过，重新生成完整便携目录与 ZIP。
- 正式 `dist/WhisperSubtitle/WhisperSubtitle.exe` 启动 36 秒后，打包 Worker 持续存活且 `127.0.0.1:1420` 无监听；退出后无残留进程。
- `corepack pnpm check`：通过，Web 20 个测试文件、82 项测试通过。
- `./whisper_env/Scripts/python.exe -m pytest -q`：361 项通过。
- `corepack pnpm e2e`：12 项通过。
- Rust `cargo fmt --check`、`cargo test --locked`、严格 Clippy：通过，34 项通过、2 项忽略。

## 结论

开发期现在可以使用快速的 localhost Vite/HMR，正式产品的离线边界没有改变。`apps/` 当前双包结构应继续保持；本期有价值的目录维护是明确源码与生成物责任，而不是迁移标准目录或按文件大小拆分。
