# 执行清单卡片配置入口

## 目标

让 `PRE-FLIGHT CHECKLIST` 下的四张状态卡片具备与其他工作区卡片一致的点击机制，同时保持它们只汇总状态、不形成选中项。

## 变更

- 四张清单卡片改为原生按钮，并复用统一 `selection-card` 的鼠标悬停、键盘焦点和按压反馈。
- “版本与模型”“媒体信息”“输出策略”“执行方式”分别滚动到当前识别模式、输入来源、文件输出和任务完成操作，并把焦点交给对应的可操作控件。
- 清单卡片不设置 `aria-pressed`、`is-selected` 或勾选标记；警示配色仍只表达配置待补充状态。
- 保持现有 2×2 网格、等高等宽、文字左对齐和大字号自适应布局，不改变任何工作区数据或任务提交逻辑。

## 验证

- React 组件测试覆盖四张卡片的按钮语义、无选中态约束和目标焦点转移。
- Playwright 覆盖统一按压反馈、四条配置路由、无 `aria-pressed`/`is-selected` 以及既有布局回归。
- `corepack pnpm check` 通过：20 个测试文件、82 项测试通过；仓库卫生、记忆、生成目录、格式、Lint 和 TypeScript 检查均通过。
- Web 生产构建与 Playwright 通过：13 个桌面工作区场景全部通过；默认字号全页截图确认卡片布局与文字左对齐未发生变化。
- `corepack pnpm desktop:build` 通过；Release 开发产物启动后主窗口句柄有效，受控 `development-python` Worker 子进程持续运行并完成启动，随后桌面与 Worker 均正常退出。
- 产品代码变更仅限 `apps/web`；不改变 Tauri、Worker、Desktop IPC、Preset 或输出行为。
