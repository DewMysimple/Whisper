# 重塑执行前任务清单

## 目标与范围

用户要求只修改 `apps/web` 的浏览器开发界面：删除启动卡片中的“媒体队列”表达，把该区域重塑为任务执行前可核对的清单，并展示版本、模型、媒体数量与时长、输出策略等真实状态。同时要求保留并提交 `apps/web/runStart.cmd`。

## 实际变更

- `LaunchCard.tsx` 将原先分离的启动操作区与媒体队列合并为一体化执行前清单；清单按“版本与模型、媒体信息、输出策略、执行方式”组织，不改变任务提交逻辑。
- 媒体信息同时显示媒体数量、输入来源数量、格式化时长和精确秒数；未知时长会明确标识，不把未知值计为零时长。
- 输出清单展示当前格式、跟随媒体或自选目录、同名冲突策略；执行清单展示转录/翻译任务、完成后操作和 Worker 状态。
- 输入来源的单项移除与清空能力保留在按需展开的管理区，不再以“媒体队列”占据主视觉层级。
- 卡片采用一个连续背景与一组分隔行；状态徽标像其他工作区卡片一样位于 heading 右侧，顶部对齐英文步骤标签，不与中文标题行对齐；标题间距与其他工作区卡片一致。卡片允许由右侧清单自然撑高，同网格行左侧面板随右侧底线对齐。
- 清单的外层、四个信息项和启动按钮区增加纵向留白，由右侧内容自然决定高度。四个信息项参考预设选择卡片，改为两排两列的独立内卡片，每张按“图标、类别、主值、说明”纵向排版，并统一圆角、细边框和浅表面。清单首排顶边与左侧预设内卡片顶边对齐；待补充提示色覆盖完整媒体内卡片，不再产生图标左侧的短线或截断色块。
- 空输入状态不再显示“添加媒体后……”的冗余说明；只有真实阻塞或已有媒体待核对时才展示状态提示。
- `Ctrl + Enter` 提示紧跟在启动文案右侧，并与主操作一起置于同一个按钮框中，共享背景、边框、圆角、阴影和禁用态。清单图标统一使用相同线性图标、尺寸和容器规范。
- 浏览器 Mock 输入补充确定的媒体时长，以便 Vite 开发服务器直接展示并回归“多少个、多少秒”的清单信息。
- `SourcePanel.tsx` 的“媒体队列”文案同步改为“任务清单”。
- 保留并提交用户新增的 `apps/web/runStart.cmd`；当前监听进程的 `vite --open` 命令与该入口一致，`http://127.0.0.1:1420` 返回 200。

## 边界

- 产品代码变更仅位于 `apps/web`；未修改 Tauri、Rust、Python Worker、Desktop IPC v1、Preset、输出规则或正式发布产物。
- 本次只改变执行前信息呈现与浏览器 Mock 数据，不改变真实媒体探测、任务快照或启动校验。

## 验证

- Web 单元测试：20 个测试文件、82 项测试通过。
- Playwright E2E：12 个场景通过；覆盖清单数据、输入管理、标题间距、左右底线对齐和任务启动流程。
- Vite 生产构建：通过；既有大 chunk 提示不属于本次回归。
- 工程级检查与记忆体检在提交前统一执行。
