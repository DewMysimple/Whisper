# 重构文件输出与开发态输入预览

## 目标

- 重新设计转录工作台“文件输出”，消除窄栏中标题、说明和控件互相挤压的问题，并与现有内卡片体系保持一致。
- 将“查看并管理输入来源”从原地展开改为跳转“任务监控与记录 / 任务监控”，在“媒体文件进度”中按单个媒体展示。
- 修复开发服务器中当前输入与任务监控不同步的问题；没有新输入时继续显示上一轮监控任务，有新输入时实时显示待处理文件预览。
- 清除执行清单快捷卡片强制滚动页面的副作用，并删除清单就绪后的冗余说明。

## 变更

- 文件输出按“保存位置、文件格式、写入规则、完成动作”重组为四张单列宽内卡片。最终方案不使用窄栏 2×2，格式名称、说明、下拉框和完成动作均获得完整横向空间；自选目录下的媒体旁副本仍作为独立附加卡片。
- 格式卡片的悬停样式只作用于未选中项，已选中的橙底白字图标不会再被浅色 hover 背景覆盖而泛白。
- 同名文件策略移除无法融入主题的 Windows 原生下拉，改为三段式圆角选择卡“覆盖、跳过、重命名”；确认时机和安全重命名含义保留在卡片说明中。
- 执行清单输入来源入口改为导航按钮，直接打开任务监控；旧的折叠列表及其遗留样式删除。
- 输入来源导航收敛为单行“查看媒体文件进度”，不再重复上方媒体卡已经展示的来源数、媒体数和去向说明。
- 新增 `developmentInputPreview.ts`：只在 Mock 开发桥中把当前输入转换为非持久化的待处理任务预览；目录按媒体数量展开为逐文件行。它不写入任务历史，也不改变 Tauri/Worker 的正式任务状态。
- 任务监控优先显示开发态输入预览；输入为空时回退到原 `monitoredTaskId`，因此上一轮完成状态保持不变。输入数组变化会由 Zustand/React 实时刷新预览。
- 执行清单四张配置卡片只使用 `focus({ preventScroll: true })` 转交焦点，不再调用 `scrollIntoView`；页面导航统一回到顶部。
- 删除“任务清单已更新，确认无误后开始本地处理。”。

## 验证

- Vitest：22 个测试文件、86 项测试通过；覆盖 Mock 目录逐文件展开、实时输入刷新、无新输入时回退上一轮完成任务、无强制滚动以及既有输出行为。
- Playwright：13 个桌面工作区场景通过；覆盖输出区四张单列卡片、无内容溢出、已选格式悬停配色稳定、来源入口导航、10 条逐文件预览和清单卡片点击后滚动位置不变。
- Web 生产构建通过。Vite 仅保留既有大于 500 kB 的 chunk 提示。
- Tauri Release `--no-bundle` 构建通过；启动生成的桌面 EXE 后，主窗口与 Python Worker 均成功就绪，随后已正常退出烟测进程。
- 视觉截图确认默认输出区不再截断格式名称，任务监控从页面顶部显示逐文件进度。
- 正式桌面仍使用真实 Tauri/Worker 任务事件；Mock 输入预览不会进入 Release 任务协议、任务历史或输出逻辑。
