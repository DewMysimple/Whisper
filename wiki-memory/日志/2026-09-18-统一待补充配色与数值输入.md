# 统一待补充配色与数值输入

## 目标

- 让执行前清单的“待补充”和相关需要关注卡片同步 SRT“选择以启用”的柔和强调色，不改变现有图标。
- 修复工作区尺寸数值框中末位数字受 WebView 原生数字控件和内部焦点样式干扰的问题。
- 让桌面框架、工作台内容和 Worker 日志三组字号都能直接输入整数，同时保留加减调节。

## 实际变更

- “待补充”徽标、需要补充的媒体卡片及其图标改用与“选择以启用”相同的强调色前景和柔和背景；警告、媒体与字幕图标均保持原样，已就绪绿色状态不变。
- 新增可复用的受范围约束整数输入，供工作区宽度与三组字号共同使用；支持直接键入、加减按钮、上下方向键、Enter 提交、Escape 还原和失焦范围收敛。
- 数值输入改用 `type="text"` 与 `inputmode="numeric"`，避开 WebView 原生 number 微调器；数值和 `px` 使用独立视觉单元，尺寸字段增加可用宽度。
- 宽度与字号数值统一使用等宽字体、同一字号和字重，数值本身按完整控件几何中心定位，右侧 `px` 不参与居中计算；宽度值继续使用强调色，字号值保持正文色。
- 内部 input 明确移除 border、outline 与 box-shadow，焦点只显示在完整外层控件，消除用户指出的双层“假内框”。
- 单元和浏览器测试更新为读取可编辑数值，并固定检查未启用图标、同步配色、直接输入、单位分格以及聚焦 input 无内部视觉框。

## 验证

- Vitest：24 个文件、94 项测试全部通过。
- `corepack pnpm e2e`：14 项 Playwright 全部通过；全屏截图确认工作区宽度与三组字号布局无挤压，聚焦字号控件只保留一层完整外框；浏览器断言同时固定数值居中、两类输入的字体参数一致及宽度值保持默认橙色。
- `corepack pnpm desktop:build`：Web 生产构建与 Tauri Release 构建通过。
- Release EXE 烟测：主窗口和受控 Worker 正常就绪；桌面退出码为 0，Worker 无残留进程。

## 边界

- 未改变 Desktop IPC v1、Preset、输出规则、字号和宽度的持久化范围或原有 Lucide 图标。
- 数值输入仍只接受现有范围内的整数；此任务没有扩大用户配置的合法区间。
