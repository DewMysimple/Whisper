# 任务监控与记录深度维护

## 目标与基线

用户授权继续深度分析、整改“任务监控与记录”，重点解决 UI 修改越来越混乱、原规则修改后不生效的问题。基线为 `1466435`，开始时 `master` 工作树干净。本轮只调整该工作台、关联详情展示和前端维护门禁；未修改 IPC、Python、Rust、Preset 或转录输出契约。

## 根因与整改

- 任务 CSS 混在一万余行全局样式中，多代 `.view-content`、`.is-expanded` 和 `!important` 覆盖掩盖了原规则；还保留无调用方的紧凑历史分支及对应旧样式。迁出并合并为 `task-workspace.css`、`task-monitor.css`、`task-history.css`、`task-date-filter.css`，按选择器／条件集中修改，移除失效分支。全局小字规则显式排除任务页，避免再次压过组件规则。
- 任务页另设 1240px 最大宽度，导致外层工作台宽度偏好无效；现继承外层可用宽度。管理卡 `overflow: hidden` 裁切日历，现保持弹层可见并由子区域保留圆角。日历打开时聚焦有效日期，Escape 返回触发按钮。
- 原组件同时承担页面、历史列表、卡片、删除和恢复确认，定位修改困难。以 `components/tasks/TasksView.tsx` 为唯一入口，历史容器／卡片、逐媒体列表、处理链路、日期与恢复确认分别负责各自行为；`TaskHistoryCard` 不订阅全局 store，`TaskDetail` 按任务 ID 重建临时状态，避免确认状态串到下一条任务。
- 历史筛选与计数共用 `state/taskHistory.ts` 规则。监控、历史和详情共用 `taskOutputPaths`，修复仅有逐媒体输出时历史展示和操作遗漏。当前媒体匹配支持 Windows 大小写／斜杠差异；失败或取消的处理链路准确区分完成、中断、未执行，未知阶段明确显示未记录。
- 自动跟随从元素 `scrollIntoView` 改为媒体列表局部滚动，避免拉动整个页面；手动浏览仍有暂停周期。Mock／原生任务页共用输入预览计数，未知目录数量不编造为一个媒体。
- `check:styles` 递归检查源码 CSS，并强制任务样式文件归属、同条件唯一选择器／属性、无旧祖先变体和 `!important`。保留旧全局 CSS 的保守覆盖检查；增加 5 项检查器测试。新浏览器回归直接修改负责元素的原 CSS 规则，确认实际计算样式响应，防止仅靠继续追加覆盖“修复”。

## 验证

- `corepack pnpm check`：仓库卫生、记忆、模型／Preset 生成目录、样式门禁、格式、ESLint、TypeScript 与 Vitest 通过；前端为 32 个测试文件、127 项测试，样式检查器另有 5 项测试。
- `corepack pnpm e2e`：18 项通过。包含原有 15 项回归与新增日历实际命中／键盘焦点、浅深主题下原 CSS 规则生效、宽度偏好及 4／3／2／1 列完整性。
- 对转录、性能、Worker 日志、设置四个工作台进行同 DOM 基线比较：两种主题、三个宽度共 24 组，最终复核 8,406,872 项计算属性无差异。任务页保留宽度、日历裁切和窄屏网格修复，不宣称其所有计算样式与旧版相同。
- 已检查浅色历史、深色历史、监控和展开日历截图。截图、比较脚本与结果保存在忽略的 `build/task-maintenance/`，不作为源码提交。
- `corepack pnpm desktop:build` 通过；Release EXE 在隔离 WebView 数据目录启动，`LOCAL IPC · READY` 与 Worker `ready` 握手成立。原生窗口验证监控／历史／日历和一条真实 CUDA float16 任务完成后的状态衔接，关闭 EXE 后两级 Python Worker 均退出。
- 原生媒体选择自动化实际提交了文件对话框此前高亮的视频，而非计划复制的短音频。该视频无识别片段，在媒体旁 `Text` 目录新建一个 0 字节 TXT；创建与写入时间一致，未删除该输出，已向用户说明。此烟测证明原生任务事件与 UI 衔接，不作为识别质量验收。后续自动化应在提交前核对应用中的实际输入快照，不能只验证文件名框赋值成功。
- `git diff --check`、记忆索引生成与体检通过。改动未包含构建目录、模型、虚拟环境或输出文件。

## 维护入口与保留项

后续修改先读 `apps/web/src/components/tasks/README.md` 的责任表，直接编辑对应组件与原 CSS 规则。Vite 开发窗口读取当前源码，Release EXE 需要重新构建才能嵌入新前端；不得通过修改生成产物排查样式问题。

现有便携发布目录与 ZIP 未重打包。已运行的用户开发服务和其他原生进程保持原状，仅关闭本轮启动的验收进程。构建仍有既有的大 JS chunk 提示，不影响本次功能验证。
