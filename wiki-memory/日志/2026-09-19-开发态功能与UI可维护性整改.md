# 开发态功能与 UI 可维护性整改

## 授权与审计范围

用户授权体检并整改工程功能、UI Bug 与可维护性，重点为频繁 UI 修改后的任务监控和历史记录。基线为当前工程源码；开始时 master 工作树干净。

审计覆盖 Vite 开发入口、Mock/真实桥接、任务提交与取消、Worker 事件归并、历史审计/预览/持久化、监控/性能/历史页面、确认弹窗、设置数值输入、日期筛选以及 CSS 级联。对照 Python 串行调度、Rust Host 断连与任务事件，未修改 Desktop IPC v1 schema、Preset、识别算法或真实输出规则。

## 已实施整改

| 问题 | 修复与回归 |
| --- | --- |
| 模型检查未完成前能重复提交；提交成功清掉等待期间新增输入 | 首次 await 前加锁，重试/续接/确认共享互斥，只移除已提交输入 |
| 重复入队、未知/终态迟到进度会污染记录或抢监控目标；Worker 断连后任务仍运行 | 幂等入队、终态守卫与 Host 断连失败归并 |
| 后一个媒体索引被当作前一个成功；部分失败可把未完成媒体全标成功 | 逐媒体结果只依据事件；保留失败、跳过和未确认结果 |
| 历史输出审计期间新任务完成，被误判为缺文件；任意预览异常直接标缺失 | 仅更新实际检查的任务/路径，错误后通过 Host 查文件存在性 |
| 同一任务关闭再打开，迟到预览覆盖新预览 | 请求序号与选中 ID 双重校验 |
| 队列等待计入执行耗时；任务/媒体时钟互相重置；完成后保留旧秒数 | Worker 执行时间锚点、独立展示时钟与终态统一耗时 |
| 目录预览编造子文件与均分时长；跳过/运行媒体误计入已处理数 | 真实目录汇总，提交后使用 Worker 清单；按媒体终态计数 |
| 按整体百分比猜处理链路，批量任务阶段错误 | 在前端投影中保留原始 stageCode，按机器阶段码选择处理步骤 |
| React effect 重挂载重新恢复磁盘历史，把活任务标中断；连续进度可能一直延迟保存 | 只首次恢复 store；150ms 节流保存，pagehide/清理 flush，捕获存储失败 |
| 原生监听器部分注册后失败会泄漏；旧轮询覆盖新状态 | 逐项登记/释放、失败可重试、销毁与 Host/模型版本校验、健康轮询互斥 |
| Mock 同时运行任务、只报告第一个媒体、丢失选中输出格式、重挂载重复初始化日志 | 串行模拟逐媒体事件和所选输出组合，取消已卸载订阅回调，日志只初始化一次 |
| 弹窗每次计时刷新抢焦点、嵌套点击关闭父层、终止目标随监控切换 | 共享焦点生命周期、隔离嵌套事件、固定确认任务快照 |
| 设置数值 Escape 仍因失焦提交截断值；日期重开沿用旧范围起点 | 显式丢弃数值草稿，日期新会话重置起点 |
| SRT 自定义参数显示成默认；输入去重与监控选择规则重复 | 共享草稿判定、输入去重与监控数据纯函数 |
| Worker 单任务执行拆分后保留 7 个无用途导入 | 删除未使用依赖，并将剩余模块导入归位 |
| CSS 同条件补丁反复覆盖 | 删除 412 条已被后续覆盖的声明，共减少 636 行；新增 check:styles 门禁 |
