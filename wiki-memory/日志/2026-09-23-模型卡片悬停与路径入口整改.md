# 模型卡片悬停与路径入口整改

## 目标与范围

用户反馈“模型与参数”卡片悬停闪烁、版式不满意，要求隐藏明文路径，改由参考图的文件夹图标进入模型目录，并与转录工作台卡片共用公共模块。本轮针对开发态源码；开始时 Git 工作树干净，不重建正式便携版。

## 实现

- 模型卡将选择与目录动作拆开。模型选择沿用转录工作台清单的公共 `CardButton`，文件夹按钮沿用 `IconButton`；未安装模型仍不可选择，但可打开目录。卡片改为紧凑的名称、能力说明和状态／容量布局，保留等宽等高网格。
- 模型选择的悬停去掉公共卡片的大面积内阴影叠层，卡片表面只用边框与背景色变化，不移动命中区域；同时保留键盘焦点反馈和选中状态。
- 不再渲染模型明文路径或包含路径的检查说明。桌面端通过 typed bridge 的 `openModelDirectory(modelId)` 请求 Host：已安装时打开实际模型文件夹，未安装时创建／打开模型根目录，并提示按注册模型 ID 放入子文件夹、刷新清单。Host 只接受注册模型 ID，不从 UI 接收任意路径；Desktop IPC v1 和 Worker 不变。浏览器 Mock 提示需要桌面开发版执行资源管理器动作。

## 验证

- `corepack pnpm check` 通过，Web 单测 149 项；`cargo fmt --check`、`cargo test --locked`（38 通过、2 项环境相关忽略）、`cargo clippy --locked --all-targets -- -D warnings` 通过。
- `corepack pnpm e2e` 完整 35 项通过。新增浏览器用例检查公共卡片、路径不显示、未安装卡仍可点目录图标、目录动作不误选、悬停时按钮几何与阴影稳定，并输出浅／深色截图。
- E2E 所需静态 Web 构建只用于预览验收；没有重建桌面 EXE、冻结 Worker 或正式 `dist`。
