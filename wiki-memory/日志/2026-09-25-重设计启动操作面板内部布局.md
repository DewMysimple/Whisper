# 重设计启动操作面板内部布局

## 目标

针对开发服务器调整转录工作台的媒体进度与本地转录区域：未选择输出格式时不再在启动区重复提示；操作区与左侧“模型与参数”入口卡同顶同高；重新设计内层排版和视觉融合。

## 变更

- 保留完整外框，并将内部重做为并列双卡：窄幅媒体进度次操作卡与更宽的转录主操作卡都填满同高区域，主按钮中的播放图标、标题和快捷键改为纵向布局。
- 操作外框与左侧 `WorkspaceEntryCard` 同顶同高；媒体卡始终占位，无输入时禁用，避免操作区跳动。
- 从启动阻塞状态中移除“还需启用至少一种输出格式，完成后即可执行。”；无其他阻塞时状态行隐藏。输出设置区继续显示格式选择要求，其余阻塞原因保留状态文本和无障碍关联。
- 更新交互契约，覆盖卡片几何、并列填充、外框和格式提示不重复；补充 Git 对 JS/TS/CSS/HTML/Rust 的 LF 规则，以匹配 `.editorconfig` 并保证 Windows 下 Prettier 检查读取 LF。
- 仅修改开发态源码和记忆，未重建或覆盖 `dist`／EXE。

## 验证

- `corepack pnpm check` 通过：仓库卫生、记忆、模型／preset 目录、样式归属、Prettier、ESLint、TypeScript 与 Vitest（37 个文件、155 项测试）。
- `WHISPER_E2E_PORT=4175 corepack pnpm e2e` 通过：38 项 Playwright 测试。
- 开发页和 E2E 截图确认操作外框与“模型与参数”入口卡同顶同高；两张内卡等高并列，浅色／深色均可辨识。
- `memory_lint.py index` 与 `memory_lint.py check` 通过。

## 结果

输出格式缺失提示只保留在格式选项区域，启动区不再重复；其余阻塞说明仍按需显示并关联主按钮。改动只进入开发态源码，未更新 `dist`／EXE；不涉及 IPC、Preset 或输出行为。
