# 校准四预设并修复配乐旁白漏识别

## 目标与授权

分析用户提供的 Turbo 中文防幻觉输出与人工核对文本差异，并调整默认参数。用户明确“所有版本”为四个转录预设，不要求验收六个模型。用户媒体和参考文件保持只读；实验输出写入任务独立、被 Git 忽略的 build 目录。

## 诊断和实施

- 旧默认值复现用户原正文，302 字符参考中有 6 替换、32 删除，CER 12.58%。主要问题是 VAD 在解码前过滤配乐中的轻声旁白，并非 TXT 后处理删句。
- 四预设统一 VAD threshold 0.05、静音等待 2000 ms、边缘补齐 600 ms，关闭前文续写；保留 VAD、beam 5、模型校准与各自后处理。最终均为 6 替换、0 删除、1 插入，CER 2.32%，遗漏的 32 字全部恢复。
- 显式固定继承窗口为 30 秒，修复 faster-whisper 共享 FeatureExtractor 保留前任务自定义窗口的问题；真实提取器的 20→默认回归覆盖四预设。
- 更新 Python 唯一参数源及生成 Web 投影。已有用户覆盖仍优先，恢复默认后应用新参数。
- 修复 benchmark 的旧输入路径，将原固定英文音频字节级复制到正式夹具目录；归档原件只读。修正 schema 3 门禁、模型校准后的有效参数记录和 Windows 换行比较。
- 四份旧 CLI golden 的标点／分行已落后于当前后处理；先分别跑旧、新参数确认当前完整文本相同，再更新 golden。识别词句没有因此改写，中文真实夹具 golden 保持原值。
- 实测重建 24 次 GPU benchmark，全部匹配当前完整文本 golden。后续只修正基线的 LF 文件哈希和实际模型校准参数元数据，计时样本保持原始值。

## 验证

- Python 全量 434 项通过；`corepack pnpm check` 通过（Web 155 项、样式 12 项、生成投影／格式／lint／类型／仓库体检）；记忆体检 102 页通过。
- 中文固定语音／配乐混合、英文合成语音／配乐混合维持零正文字符错误；四预设数字静音为空。纯音乐旧、新参数都可能产生短语幻觉，记录为能力限制。
- `buildStart.cmd` 完成全量 Release；冻结 Worker 两个中文夹具任务匹配既有 golden，四个用户媒体任务与候选完整文本一致，CUDA float16、每轮只加载模型一次、健康检查及关闭均通过。
- manifest 930 项，目录／ZIP 各 931 个文件，ZIP 全量 CRC 和外层三项 SHA256 通过。
- 正式 EXE 通过真实 Tauri bridge 确認 packaged-sidecar 就绪、`system.health` 为 ok，12 秒后仍为同一 Worker，关闭后子进程已回收；本次检查使用隔离 WebView 测试配置目录。

## 留存与边界

详细可复用说明位于 `docs/development/transcription_calibration.md`。原始实验和验收记录位于本机忽略目录 `build/analysis-20260926/`，不提交个人路径、参考全文、模型或发布产物。

只有 Turbo 做了真实验证；这组默认值不能称为全音频、全模型最优。同音词和纯音乐幻觉仍有残余。首次全量 Python 验证中曾因手动设置子进程 UTF-8、父进程按 GBK 解码而失败；清除该临时环境设置后全量通过，不涉及产品代码修复。

当前 WebView2 153 对提权进程忽略环境变量形式的调试参数，最初 CDP 连接未成功；按微软官方行为说明，临时对本程序设置专用调试端口完成只读握手检查，并在 finally 恢复注册表、关闭端口与测试进程。该设置未进入应用配置或发布产物。
