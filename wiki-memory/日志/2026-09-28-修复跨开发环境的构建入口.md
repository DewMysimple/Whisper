# 修复跨开发环境的构建入口

## 原因与范围

实际运行原 `buildStart.cmd` 在 `Resolve-Path` 阶段失败：底层构建脚本默认强制寻找工程 `whisper_env/Scripts/python.exe`。这是环境目录名称绑定，CMD 本身通过脚本位置解析工程，未绑定某个盘符。

本机 Git reflog 显示本日拉取了其他环境完成的发布／瘦身提交；模型、虚拟环境和 dist 被 Git 忽略，本机没有这些目录，也未发现 Cargo。用户进一步确认这里只是另一套开发环境，完整 dist 在其他开发环境构建，并非清理误删。本次不恢复旧组件、不下载模型、不安装桌面工具链，也不在这里补建正式版。

## 修改

- 在 `prerequisites.ps1` 集中 Python 发现、Cargo 查找和构建前检查。Python 可使用现有活动／工程环境、PATH 或 Windows launcher；显式无效参数保留错误，避免悄悄使用其他环境。
- 本地模型支持显式参数和既有模型环境变量。缺少 Python、模型、Node/Corepack 或 Cargo 时在创建／删除构建目录前汇总问题。
- 新增 `-CheckOnly`，执行本地条件检查且保持目录不变；读取模型时禁用 Python 字节码写入。
- CMD 保留退出码和按键停留，成功提示不再把仅检查误报为已生成产物；失败时提示 Web 预览入口。
- 更新发布指南和 active 记忆，修正知识页仍将 ZIP 视为默认产物、默认保留 stage 的旧描述；已封存历史日志不修改。

## 验证

- 原脚本实际复现缺少固定解释器路径；修改后真实 CMD 可找到本机 Python，并汇总模型和 Cargo 缺失，退出码为 1，无构建／下载／目录替换。
- 11 项新增 Windows PowerShell／CMD 入口回归通过：没有旧环境时回退、活动环境优先、显式参数优先、失效活动环境、无可用 Python、参数错误、模型环境变量／显式覆盖、相对与带空格路径、结构模型缺失、普通构建失败前保留诊断、仅检查成功及非零退出码传递。结构模型夹具不用于真实推理。
- 隔离临时 pytest 工具环境运行 `tests/test_packaging.py`、`tests/test_release_prerequisites.py`、`tests/test_workspace_cleanup.py`：33 项及 2 个 subtest 通过；未恢复应用开发环境或安装推理依赖。
- Web 157 项、样式检查器 12 项、Preset 投影、Prettier、ESLint 和 TypeScript 检查通过；工程卫生与记忆检查通过。
- 完整 `corepack pnpm check` 在模型目录投影步骤因本机缺少 `rustfmt` 而停止，其后门禁已分别执行通过。未伪造格式工具或修改生成结果绕过检查；本轮不能写成完整通用检查通过。
- 按用户说明，本轮不在此机器重建完整 Release 或执行 EXE／真实媒体验证。未改产品运行时代码、依赖、IPC、模型定义、Preset 或 UI；实际打包机器仍需执行正式发布验收。

## 收尾

`workspace:clean` 预览通过；实际 `workspace:finish` 因源码机器没有正式版 manifest 受保护地退出，没有删除内容。随后使用既有 `workspace:clean:apply` 完成缓存白名单清理，不绕过发布保护、不创建假 manifest 或产物。`workspace:size` 最终记录 **213,710,466 字节（0.20 GiB），12,526 文件**，主要为保留的 Node 依赖；后续本日志和 Git 提交带来少量字节变化。未生成 dist、模型或应用虚拟环境。
