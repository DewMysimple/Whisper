# 输出安全、诊断语义与持续集成

## 目标与基线

按用户提供的执行背景与第一轮提示词，仅实施输出碰撞、Qwen 解码诊断语义和 CI，配套修复 Python 3.10 测试兼容及过期文档。基线为 `e0de8e22ead7e03ac51210cf44e8dc1c9be67997`，当前分支 `master`；用户未跟踪的 `prompt/` 保留且不提交。

本机是 Windows 11 x64，开发解释器 Python 3.14.2，Node 24.16.0、pnpm 10.34.5、Rust 1.97.0，RTX 5070 Ti 与 Turbo、Qwen 两档及共享对齐模型可用。发布前置检查已通过；历史验收不代替本轮实测。

## 实际修改

- 输出规划把磁盘旧文件与批内／活跃任务占用分开。覆盖只允许旧文件，预留碰撞使用现有 `task.conflict` 拒绝；自动重命名、跳过及终态释放保持原契约。
- Web 的生成文件汇总排除 skipped 媒体的冲突路径，防止把旧文件或尚未落盘的活跃任务目标计入新结果。保留任务级真实输出及跳过关联，继续服务续接检查。
- Qwen 语言／术语核查与解码诊断共用严格 v1 对象，保留兼容载体，消费端依注册表生成的能力事实过滤不适用的统计。Whisper 真实零值、新旧 Qwen 历史与未记录诊断分别展示，不增加 schema 字段或伪造概率。
- 新跨端夹具捕获 Rust 既有校验漂移：`max_temperature` 错用可空校验器，实际接受 null，而 schema、Python 和 Web 均要求数字。Rust 已对齐既有 `number [0,1]` 约束，未修改 schema。
- GitHub CI 复用现有脚本，普通无模型检查与真实 GPU／冻结发布验收分开；保留 Python 3.10 支持，开发依赖增加条件 TOML backport，wheel 入口测试使用结构夹具而非本机模型。
- 首次新鲜发布环境解析到 PyAV 19.0.2，真实冻结转录捕获其移除 `metadata_errors` 与 faster-whisper 1.2.1 的不兼容。基础依赖约束为 `av>=11,<19`，发布按 Python 条件固定 18.0.0（3.11+）／17.0.0（3.10）；加入真实 PCM 解码测试，不依赖模型或 GPU，不改解码算法。隔离 av19 环境新增测试先失败，av18 与 av17 实测通过；3.10 的真实执行交给远程矩阵。
- README 同步当前模型／参数和硬件工作台、Qwen 能力、输出策略与诊断语义；用户说明及架构文档同步。
