# 退出卡顿内核诊断与 Host 回收修复

## 目标与现场

用户报告 Whisper、Qwen 都会在任务完成后关闭软件导致整机卡顿，排查期间确认仍在卡顿。基线为当前 master；未跟踪的 `prompt/` 保留且不提交。

现场旧 Worker 已返回退出码 0，但只剩一个线程持续占满单核，系统态累计超过 3,900 秒，约 1 GiB RSS 未回收；再次 `TerminateProcess` 被拒绝。Host 无响应，结束 Host 后用户确认整机仍卡顿。

5.754 秒 ETW PROFILE 采样得到该线程 5,677 个样本，其中 5,639（99.33%）指令位于 NVIDIA `nvlddmkm.sys`。微软匹配内核符号解析显示调用路径为：

`NtTerminateProcess → PspExitThread → PspExitLastThread → PspExitProcess → PspCallProcessNotifyRoutines → nvlddmkm.sys`

本机 NVIDIA 驱动为 616.92（文件版本 32.0.16.1692）。这是进程退出通知中的显卡内核驱动卡住，用户态 Python／模型析构已过去。尚不能确定具体哪项 CUDA 操作触发；不能据此断言所有同版驱动或所有机器必现。终止请求和 Job Object 无法保证清掉已卡住的内核回调，若不恢复可重启清理再验证驱动兼容性。未擅自重启电脑或更改驱动。

原始 ETL、现场快照、统计、符号栈和验收报告已保留在忽略目录 `tests/benchmark/runs/2026-11-02-shutdown/`，不提交二进制诊断；可从 ETL 重新导出采样 CSV。临时符号缓存和 UIA profile 不作为源码或用户数据保留。

NVIDIA 的 [R615／Windows 616.92 官方发布说明](https://docs.nvidia.com/datacenter/tesla/tesla-release-notes-615-71-09/index.html) 也列出升级驱动后 CUDA 进程偶发死循环、无法结束的问题，并要求跨分支升级后重启。该说明面向 Data Center 驱动，本机为 GeForce；它只支持优先重启复验，不能替代本机 ETW 证据，也不能据此认定具体触发条件完全相同。

用户补充最近没有升级驱动，因此不按“驱动刚升级未重启”直接归因。结束旧 Host 数分钟后，旧 Worker 最终从系统消失，用户明确反馈“现在不卡了”，本轮未重启。随后仅运行一次旧冻结 Turbo 的 command 退出基线：真实短音频成功，空闲 CPU 0%，关闭 0.4675 秒、HANDLE signaled、退出码 0，Worker 及观测到的后代均无残留。这证明本次卡死并非每次短音频退出必现，不能因这一次通过宣布驱动问题已修复。

## 软件层修复

- Tauri 退出回收移到后台，避免在主事件线程等待 Worker。
- Host 的关机命令应答与进程退出共用原有 15 秒预算；没有子进程时重复退出立即返回。
- 删除 Windows 强制终止后的无界 `Child.wait()`，驱动结束进程迟迟不完成时 Host 不再无限挂住。
- Windows Job Object 归属 Worker 与后代，超时／Host 异常退出时请求整组回收；这不等于保证内核卡住的进程已消失。
- 启停发布互斥，退出期间迟到的 ready 事件不能重新打开命令通道。
- 不改 IPC v1、模型、preset、识别输出和正常 UI 操作。

新增显式工具 `tests/benchmark/run_shutdown_validation.py`，逐个测试三种模型的 shutdown／EOF，Qwen 包含 SRT 对齐，记录 CPU、内存、线程、退出耗时及后代。Windows 通过进程 HANDLE 信号确认真正结束，不能仅凭退出码 0 宣告回收成功；失败保留诊断并停止后续模型，避免积累卡死进程。普通单测不会启动模型。

## 交付边界与后续观察

- 当前卡顿已恢复，软件层退出缺陷已修复并通过相关验收。保留模型、开发环境、Node 依赖、真实用户 profile、媒体／输出及未跟踪的提示词。
- 不能把这次短音频矩阵通过外推为 NVIDIA 616.92 内核驱动缺陷已根治。若真实长任务退出再次卡顿，优先保留 ETW 并处理驱动兼容性；已卡在内核的进程无法由应用保证及时终止，必要时重启恢复。未修改系统驱动、CUDA context 或全局设置。
- 验收后按约定执行白名单清理，原始内核诊断及验收证据保留在上述忽略目录。
