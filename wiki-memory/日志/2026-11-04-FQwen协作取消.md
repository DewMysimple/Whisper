# F：Qwen 生成循环协作取消

取消路径：桌面动作 → 原桥接 transcription.cancel → WorkerTask.cancel Event → application 可选取消能力 → Qwen StoppingCriteria。现场安装的 Transformers 5.17.0 中，Qwen 使用 GenerationMixin，StoppingCriteriaList 每 token 检查，支持安全停止。

Domain 增加可选 CancellableTranscriptionEngine，取消异常归入 domain 并从原 application 路径兼容导入。取消探针为单次调用局部参数，不进入 preset、IPC 或模型实例持久状态；Whisper 仍走原接口。解码前后、窗口间、生成前后、对齐后均检查；生成中使用真实停止条件，返回后先检查取消，不解码／对齐／导出未完成窗口。线程作用域原 finally 恢复，模型可继续下个任务，未杀进程。

## 验证

- 全 Python 573 通过，2 subtest 通过。新增推理前、窗口间、当前生成停止、连续三次取消、生成异常、线程恢复及同实例后续生成；既有 Worker 排队取消／终态／资源检查继续通过。
- 两档真实 CUDA WorkerRuntime 各连续取消三次，再立即正常执行一次，共8例。测试专用条件在第3个 token 经原 cancel 命令触发，生产条件第4次检查停止；6次 cancel→idle 为0.0444–0.0462秒，均零正式输出。后续两例三格式成功、模型各只加载一次，runtime.close 正常释放。
- 显式入口 `python -m tests.benchmark.run_qwen_cancel_validation --model-dir models/huggingface --output-dir tests/benchmark/runs/<new-run>`，不属于普通单元测试自动运行范围。
- 最终源码三模型九例固定语料复跑通过，CER／英文 WER 均维持0，静音意外文本0。逐项差异在忽略的 quality-after；单次冷启动耗时波动，未宣称吞吐改善。
- 延时仅衡量已进入生成的检查点；解码、特征前处理、单个GPU forward和对齐不能抢占，不能外推为所有桌面点击延迟。
- 正式冻结 Worker／EXE 仍待统一构建验收。当前终端 GitHub／PyPI 连接超时，先核对本地缓存能否支持原发布流程，保留失败诊断。
