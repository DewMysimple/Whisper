# Qwen 触顶自动拆窗与双视频验收

## 目标与证据

用户授权修复 Qwen 达到 token 上限后整文件失败的问题，使用两段原始 MKV 完整验证，并更新标准便携版。
旧正式版同批两个媒体分别在约 26%／17% 失败；Worker 报单窗生成达到 440 token 且未自然结束，成功 0、失败 2、输出 0。默认窗口 30 秒，未有用户参数覆盖。

## 实现

- `qwen_engine.py` 新增内部 `QwenTokenLimitError`，满预算且无 EOS 才触发二分；其他错误不重试。
- 沿用原始样本区间，按左、右顺序递归；子窗口分别识别与真实对齐，使用原媒体绝对偏移，不重新执行 VAD，不接受父窗口的截断结果。
- 子窗至少 1 秒、最多 5 层；到下限仍失败会明确报错。每次尝试退出线程作用域和异常处理后才递归，保留取消检查并释放失败 traceback 对张量的引用。
- warning 记录触顶区间、拆分点和层级；同步参数说明与 Qwen 开发文档。IPC、参数默认值、模型和输出策略保持原契约。
- 完整复放发现第二片更后面的 1306.512–1335.344 秒窗口虽自然结束，但重复生成同一句话，导致真实对齐返回超出窗口的时间戳。两个半窗重新识别／对齐均成功；将原三处对齐校验失败标为内部 `AlignmentError`，复用同一套有界拆分，保留严格校验。普通运行时异常不重试，只有成功窗口更新语言。原失败与局部恢复诊断不计为全片通过。
- 新回归覆盖嵌套拆分、奇数样本、非零偏移、对齐、正常 EOS、普通异常、取消、重试下限和线程恢复。

- `corepack pnpm check`：工程、记忆、生成投影、样式、格式、Lint、类型和 Web 195 项通过。
- 源码：第一片完整 1560.028 秒转录成功，用时 149.76 秒；补入对齐恢复后第二片完整 2734.228 秒转录成功，用时 211.43 秒。第一轮第二片失败与后续局部诊断均保留，不替代最终完整复验。
- 正式 EXE：真实 Worker 握手、PID 一致、持续就绪与 Qwen 可选通过；Host／Worker HANDLE 均完成，完整所属进程与隔离 profile 最终零残留。旧验收脚本在关闭约 0.4 秒后立即快照误报 WebView2；复制到本轮诊断目录并增加最多 15 秒的完整后代等待，实际额外等待 1.841 秒后全退出，不修改产品退出逻辑或旧报告。
- 最终 `release:build` 已从新环境完整构建并验证 5948 项清单。构建遇网络 SSL 重试后，为最终构建使用经依赖闭包和 Torch SHA256／CRC 验证的本机 pip 缓存临时硬链接 wheelhouse；仅设置构建进程环境，无源码、依赖版本或证书配置变更。
- 冻结版按原任务 en_v2、30 秒／440 token、CUDA BF16／device0／CPU threads0、42 字符单行等字幕参数完整成功：第一片 127.96 秒、第二片 205.50 秒，各 success=1／failure=0／三个输出，进度单调至 100 并经过后处理／写入／汇总。源码探测使用基准器默认 18 字符排版，不作为原排版参数的最终验收。
- 冻结版实际恢复：第一片 token 407.984–433.104 秒；第二片 token 466.280–472.760 秒及对齐失败 1306.512–1335.344 秒。三个重试区间内的字幕均正时长且不重叠。
- 冻结版六份成品均为非空 UTF-8；SRT 分别 601／1163 条，编号连续、正时长、未越媒体长度、单行最多 42 字符。TXT／Markdown 与对应成功源码输出逐字节一致。Worker 指纹与当前 dist 一致；TXT／SRT 共四份已安全写回原媒体目录并校验哈希，未覆盖既有文件。

## 输出质量边界

重试区间均要求实际重新识别与真实对齐成功，不通过修正／伪造时间戳或跳过音频验收。最终 42 字符版在非重试区间仍有 1ms 重叠：第一片 1 组、第二片 2 组；极短实质 cue 分别 6／9 条。严格结构报告因此保留 `passed=false`，不声称时间轴全绿或零漏字；任务完成和重试恢复单独通过真实 IPC 与逐区间检查验收。无人工逐字参考，未计算 CER／WER。当前事实见 [[当前状态/已知问题]]。

本轮本地诊断与报告保存在被忽略的 `tests/benchmark/runs/2026-11-11-token-retry/`；不提交用户媒体、输出、模型、本机路径或构建产物。范围外的未跟踪 `prompt/` 保留。
