# 修复原生媒体拖放与检查反馈

## 问题与修复

- Windows 上 WebView2 的文件拖放走 Tauri 原生事件，原网页拖放处理器只切换界面样式。原生监听排在五个其他订阅后，Worker 初始化失败也会一起卸载。现优先独立订阅原生进入、离开和松手事件，转录工作台的输入区由同一事件链提供高亮和提示。
- 松手时立即显示待检查数量，状态继续区分已接收和已校验。原路径、目录递归、时长和容器校验沿用 `inspect_inputs`，尚在检查时不允许提交不完整的任务。重复路径跳过检查。清除任务清单使未完成检查结果失效，同一路径可以随后重新拖入。按钮选择与剪贴板路径保留既有入口。
- Rust Host 消除顶层路径的重复元数据读取，递归发现媒体后统一排序并缓存各路径排序键。Python Worker 和 IPC v1 沿用此前实现。

## 验证

- React 测试覆盖拖入高亮、松手立即可见、检查期间禁用启动、完成后加入以及 Worker 初始化失败后的原生事件。状态测试覆盖快速重复拖放与清除后旧结果迟到。
- `corepack pnpm check` 通过，Web 197 项。Playwright 40 项通过。Rust 47 项通过，3 项按原配置忽略，`cargo fmt --check` 与 Clippy 通过。
- Windows NTFS 隔离夹具包含 8,192 个媒体路径、512 个末级目录和 512 个非媒体文件。对照变更前后源码各运行 21 轮交替热测，路径、数量和顺序逐轮一致。Rust 发现与排序的中位耗时由 36.54 ms 降至 18.70 ms，减少 48.8%。测量范围为目录发现和排序，整批检查仍包含 Worker 容器探测。
- `tools/release/assemble.ps1` 重建 React 与 Tauri Release 并更新标准便携目录。冻结 Worker、模型和 SBOM 沿用 2026-11-11 已验证物料，并核对与原清单的哈希一致。重新校验 5948 项 manifest 和外层 SHA256。冻结 Worker 的 `worker.ready`、`system.health`、两份 WAV 的时长探测及正常退出通过。
- 正式 EXE 在隔离配置下完成 Worker IPC 握手，就绪 PID 与实际受控子进程一致并稳定 5 秒，Qwen 模型可选。正常关闭后 Host 和 Worker 均以 0 退出，WebView2 后代全部回收。
- 从真实 Windows 资源管理器拖入正式 EXE。含中文和空格的单文件拖入时高亮，松手后约 36 ms 显示检查状态、80 ms 入单。两文件放在输入面板之外仍成功，约 38 ms 入单。按 Esc 取消后高亮消失，清单不变。包含 600 份实际 WAV 的目录约 36 ms 显示检查状态、220 ms 完成入单。耗时为本机夹具的逐次观察值。
- 同一套常规拖放夹具的旧版单文件／双文件／600 WAV 目录入单观察值分别为 123／174／357 ms，无原生高亮与检查提示。新版冷启动等到输入区首次出现后即拖入，当时 Worker 尚未就绪，仍收到高亮，松手 137 ms 后观测到待检查状态，约 1.304 秒后入单。新旧版在只显示裸窗口边框、WebView 输入区尚未出现时均未接收极早松手的文件，工作台可见是实际拖放起点。
- 复跑新版的单文件／双文件／目录入单观察值为 96／34／182 ms，重复拖入相同目录后总数量保持 603。旧版复跑为 70／34／353 ms，因此本机夹具的单文件与双文件入单耗时存在波动，目录两次均更快。旧版在输入区已可见且 Worker 仍启动中的场景也能接收，约 1.436 秒入单，期间无反馈。旧版该场景未复现丢单，原生测试证实的是反馈缺失以及本次改进后的反馈闭环。

## 保留项

源媒体和输出不受清除操作影响。源码、冻结 Worker 与模型作为不同构建部分验收。范围外的未跟踪 `prompt/` 保留。

## 收尾

`workspace:clean` 预览后执行 `workspace:finish`，再次验证 5948 项发布清单，按白名单清理工程构建与测试缓存。`workspace:size` 记录 40,753,338,980 bytes（37.95 GiB）、50,374 个文件。保留标准便携目录、校验文件及此前单独分发的 Qwen 专用 ZIP。

原生拖放报告保存在仓库外的本次验收临时目录。终端策略拦截了该临时目录中测试音频、隔离配置和临时目录联接的合并清理命令，测试进程已全部退出。
