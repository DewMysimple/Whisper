# 渐进媒体导入与转录计时

## 实施

- 原生拖放、文件选择和粘贴共用导入批次。输入区即显已收到路径的文件名，按条目更新检查结果或目录已查数量。整批校验结束后才可提交。清除在 Host 和 Worker 按导入标识取消，迟到事件不会影响同一路径的新导入。提交仍重新展开目录并检查有效输入、输出冲突和预留。任务中的输入、模型、参数和输出方案来自提交时的快照。
- Host 单独记录路径发现、Worker 往返和检查结果。Worker 使用两个有界 PyAV 探测子进程，按规范路径、大小和纳秒修改时间复用缓存。容器检查失败、无音轨、时长未知、连接异常、超时和取消使用相应状态。可选进度与取消能力由 `system.health` 协商。无相应能力的旧 Worker 继续使用原检查请求和响应。
- 前端提交前立即锁定本次请求，按启动检查、模型加载和取消请求更新提示。任务受理仍以 `task.queued` 为准。准备取消在安全边界生效，底层加载期间显示取消请求正在处理。模型初始化仍由 Worker 主命令线程执行。Windows stdin 读取只消费管道中已到达的字节，真实 Turbo 测试发现阻塞读取会卡住 NumPy／CTranslate2 首次导入。
- 工作台复制及导出诊断时附带应用版本、各组件独立构建信息、能力版本、模型和设备。跨进程用导入／请求／任务 ID 关联，进程内用单调时钟。浏览器记录反馈 DOM 提交和点击至终态，Host 记录自己的调用往返，Worker 记录排队、运行库准备、模型缓存、推理、后处理和写入。RTF 为单文件推理阶段耗时除以媒体时长，媒体时长未知时 RTF 为空。CUDA 精确同步耗时只在显式基准采集。
- 执行前清单保留 2×2 卡片、图标、文字字号、行高和操作区尺寸。单行与原多行各按实际可用区域省略，完整值仍在 DOM、提示或无障碍描述中。最小字号预设只剩一行说明高度，策略使用该行的独立位置，旁边的路径在剩余宽度内省略。

## 测量条件及证据

Windows 11、RTX 5070 Ti 16,303 MiB、驱动 616.92、Python 3.14.2、CUDA 版 PyTorch 2.11.0。真实测试使用仓库已有夹具及明确派生的测试条目。基线是 `92962e1c533b8df779b4c6f19e10cb51007615c8` 的标准便携版及其冻结 Worker。用户日志对应的原媒体未用于本轮测试。

- 旧冻结 Worker，5.323 秒中文 WAV，30 次重启及同进程复查。首次容器检查往返中位 33.67 ms、P95 36.12 ms，同进程缓存中位 0.27 ms、P95 0.42 ms。采样不含 Host 目录发现和界面。
- 相同 5.323 秒 WAV 重跑冻结版前后对照，每版 30 次交替运行。以下为旧 → 新的中位／P95（ms）：进程至 ready 177.13／454.44 → 159.99／273.21，首次检查 34.52／59.85 → 198.25／355.46，同路径缓存 0.30／0.49 → 6.53／10.72，32 副本首项 140.54／228.37 → 15.23／18.20，32 副本整批 140.54／228.37 → 199.51／326.62。旧版只能在整批返回时报告首项。保留后台构建导致波动期间的全部样本，新版首次检查最大 2,140.58 ms。隔离让结果更早可见，首次检查进程启动和命令等待仍有成本。
- 旧正式 EXE 从 Windows 资源管理器重复拖入 8.697 秒 WAV 30 次全部入单，松手至入单中位 93 ms、P95 161 ms、范围 35–161 ms。单次冷样本反馈 101 ms／入单 2,242 ms，600 WAV 目录反馈 42 ms／入单 221 ms。UI Automation 的采样粒度只够记录实际观察到的状态。
- 新正式 EXE 同一夹具的 30 次均成功，入单中位 96 ms、P95 167 ms、范围 40–261 ms。冷工作台单次反馈／入单 135／253 ms，两文件 38／216 ms，600 WAV 目录 50／289 ms。冷态为工作台已可见、Worker 尚未就绪。这些单次对照保留波动。新版同路径 30 次 Web 内部从接收到 DOM 提交 0–1 ms，接收到检查返回 3–13 ms、中位 8.5 ms。UI Automation 从资源管理器松手计时，在快速重复热路径中未观察到中间态。旧版没有同一 Web 指标。
- 资源管理器拖入 1,800 WAV 的目录，检查中清空，立即拖入同路径，第二次 469 ms 完成；Esc、重复路径、Worker 握手和退出均通过。新版 Host、Worker 退出码均为 0，清单和资源按本轮验收回收。
- 在 32 个未命中时长缓存的相同 WAV 副本上，已预热的 1／2 个源代码探测槽各跑 10 次，中位 153.07／79.79 ms。模型冷态与缓存热态单独计。以实际 PyAV 子进程暂停模拟挂起，另一项目在 143 ms 报告结果，同时 `system.health` 9.50 ms，取消至检查结束约 49 ms，进程句柄已结束。超时样本 8.025 秒，其余媒体就绪；清空同路径重导和进程回收通过。
- 冻结 Worker 复跑实际子进程暂停注入。正常项 201.37 ms 可见，健康检查 3.67 ms，取消至检查结束 54.16 ms，独立超时 8.014 秒。同路径重导成功，三条可见探测进程均回收。
- 冻结 Worker 的 600 个相同 WAV 副本，每版 5 次交替，首项中位 2,615.27 → 15.70 ms，整批中位 2,615.27 → 1,512.67 ms（约减少 42.2%）。此项只测 Worker，资源管理器和目录遍历另行计时。63.872 秒 Qwen 1.7B CUDA BF16 真任务执行期间，`system.health` 6.86 ms 返回同一活跃任务，另一份未缓存的特殊字符路径 15.31 ms 检查完成，转录正常结束。
- Edge 五组同条件几何对照中，四卡、图标、标签、标题、徽标和按钮的坐标尺寸差为 0 CSS px。长输出路径在四种压力配置的卡片垂直溢出为 259／324／206／422 CSS px，修改后均为 0。长中英文路径出现真实省略号，三种同名策略文字可见，覆盖约 320–360 px 局部宽度和大小预设。
- 1600×1000、100% Windows 缩放下，对相同 239 字符路径做 WebView2 前后截图。长路径出现省略号，覆盖文字完整，外框、卡片高度和垂直位置相同。旧内滚动条消失后，内容区恢复约 10 个物理像素宽度，两列各增约 5 像素，操作区相应分配。125%／150% 系统缩放未测。
- 用 `tests/benchmark/run_qwen_window_benchmark.py` 单独比较 Qwen 1.7B 串行与 2／4 窗批次。72.079 秒派生中英夹具，模型驻留，每档 3 次，端到端文件中位 7.623／3.738／2.109 秒，首次非空段中位 2.116／2.056／2.102 秒，Torch 峰值已分配显存 4,042／4,184／4,466 MiB，TXT／MD 哈希一致。派生混合夹具在三个配置都有误识别；哈希一致仅用于确认实验相对串行一致。另用 58.581 秒派生中文夹具每档 1 次做真实对齐，6.625／4.180／2.748 秒，TXT／MD／SRT 哈希一致、CER 0、16 条字幕，无重叠或非法时长。样本及批量取消和资源压力证据不足，生产继续串行。
- Qwen 1.7B 使用相同 5.323 秒中文文件、CUDA BF16，旧冻结、新源码各 3 次冷进程及 3 次同进程驻留任务。请求至排队／首个正进度／运行至完成／请求至完成的中位数（秒）为冷态 8.571／3.426／3.441／12.215 → 8.127／2.474／2.488／10.615，驻留 0.003／0.937／0.940／0.944 → 0.015／0.895／0.901／0.917。两边冷态端到端区间重叠，且新源码与旧冻结运行形态不同。各任务黄金文本一致，每个进程只加载模型一次。新源码首个非空段中位冷／热 2.474／0.895 秒，推理 RTF 0.465／0.168。
- 一次显式模型预热耗时 7.470 秒，请求至队列降至 0.153 秒，预热加首任务共 9.996 秒。该实验验证准备等待可以前移，生产仍按需加载。首段时间已可测，待验证预览的可用性与节流后再考虑显示部分文本，最终文件依然由原子写入确认。
- 旧冻结版与更新源码分别运行 Turbo／Qwen 0.6B／Qwen 1.7B 的中英文短夹具和 120 秒静音，全部 9 项成功。TXT／Markdown／SRT 与各自基线逐字节一致。语音短夹具 CER／WER 为 0，静音无意外文本。真实 CUDA 序列 Qwen 1.7B → 0.6B → Turbo → 1.7B 通过。三次执行中取消响应约 24／49／88 ms，无正式输出，随后任务仍可成功。冷模型准备取消约 9.5 ms 登记，在 10.04 秒后安全结束，期间未排队、未写输出，两次后续任务复用该模型。
- 本轮冻结 Worker 实际通过两档 Qwen 的 SRT 对齐、Turbo 黄金输出、模型切换以及三次运行中取消。冷模型准备取消 10.65 ms 获得确认，6.764 秒到达安全结束，期间未入队、未创建输出，后续两次复用同一模型的黄金任务成功。冻结 Worker EXE SHA-256 为 `da86b93b08daf6477790e0249d8acd4011295e3a9349a3fe25a0e549853acda7`。

## 可复验入口

- `python tests/benchmark/run_media_inspection_benchmark.py --baseline-worker <旧冻结 Worker> --worker-executable <本轮 Worker>` 在同机同夹具下交替顺序运行，冷定义为重新启动进程，热定义为同进程 stat 缓存命中。另比较已热的 1／2 个探测槽。
- `python tests/benchmark/run_qwen_window_benchmark.py --help` 查看显式批量、样本生成和对齐开关。报告保留所有样本、显存与文件内容哈希。
- `python tests/benchmark/run_worker_gpu_validation.py --help` 查看相同请求的冷模型、模型驻留和显式预热对照。准备阶段单独记录，预热成本计入预热加首任务。
