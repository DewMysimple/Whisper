# 执行前清单操作区紧凑布局

根据用户提供的 Pre-flight 整改任务书，在 `LaunchCard.tsx` 和 `styles.css` 将第三行改为全宽转录主按钮，移除原并列操作容器表面。主按钮横排图标、动作与键帽；窄容器隐藏键帽。底行显示真实检查、准备、确认、空状态或阻塞信息，右侧保留原生媒体进度按钮。无媒体时入口禁用，可执行时键盘按主按钮、次按钮的顺序访问。双列下清单面板按内容收高，避免压缩操作区后留下多余底部留白。

`canStart`、准备取消、标准版本确认、同名文件与关机确认、Ctrl+Enter、任务监控导航及各项摘要沿用原链路。保留执行阻塞的 `role="status"` 与 `aria-describedby`。运行时差异限于 Pre-flight 展示；媒体区域的来源组件、样式、路径导入、剪贴板和原生拖放事件链均沿用现有实现。

## 对比验收

- 同一 Edge 分别运行修改前和修改后的应用。覆盖 1680×1080 浅色、1440×900 深色、1180×720 和 1920×1080 深色 18px 工作台字号，以及更窄的浏览器压力视口。空态、拖入、媒体检查、就绪及准备场景中，拖放区与来源面板的坐标、尺寸、上下留白和计算样式逐项相等；标题及四张摘要卡的尺寸和位置相等。
- 常规操作区为 100px（原 142px），主按钮 60px、次入口 36px。操作区内部无横向溢出，两项操作焦点清晰。小于软件最小窗口宽度的浏览器视口保留原有全页横向滚动。沿用原有启用态橙底白字，浅色／深色默认对比度约 3.11:1／2.87:1；禁用文案提高到约 5.02:1／6.15:1。独立系统 DPI 与屏幕阅读器未专项实测。
- 增补 App 集成与 Playwright 断言，覆盖检查状态、Worker／无效路径／输出目录阻塞、准备中的 Ctrl+Enter 防重复、取消准备、宽度和次入口热区、键盘顺序及较大字号下长字幕模式文案。保留已有点击启动、确认流程和媒体监控用例。

## 既有导航行为

旧标准 EXE 与新候选 EXE 在无运行任务且无当前监控任务的干净配置中，都由“查看媒体进度”进入任务工作台并落在历史子页。切换到监控子页后可查看当前输入。原因是 `setActiveView('tasks')` 覆盖入口发出的子页选择。任务书要求保留现有导航逻辑，本轮记录于 [[当前状态/已知问题]]。
