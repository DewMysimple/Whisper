# 稳定媒体拖放外框并对齐转录操作

用户提供的截图显示，文件拖入后虚线框从约 359px 缩至 275px，整个输入卡片增高约 34px。渐进检查列表作为卡片的直接网格子项插入后，占用了剪贴板入口的弹性行。上一轮的测量仅比较两版各自的同名状态，两版都存在相同的状态间跳动。

检查列表现显示在拖放框的下部，溢出时在框内滚动。输入卡片、虚线框和剪贴板入口沿用空闲时的位置与高度。拖入高亮、待检查提示、文件名、检查状态及检查完成后的清单均沿用既有数据与事件。

双栏工作台中，主按钮吸收「文本识别模式」与「任务清单」之间的行高差。平衡字号下按钮从 60px 增至 102px，左右面板的上下边缘齐平。较大字号下实测按钮约 118.33px，单栏时维持 60px。状态和媒体进度行保持 36px，配置摘要仍与版本卡片共用行高。

## 验证

- 同一 Edge 测量七组视口、主题和字号，含 1180px 桌面最小宽度。空闲、拖入、检查、就绪与准备状态的输入卡片、虚线框、剪贴板位置与尺寸均相等，并与上一版空闲布局一致。浅／深色和不同字号下动作区无横向溢出。
- `corepack pnpm check` 通过，包含 200 项 Vitest。`corepack pnpm e2e` 完整构建通过，48 项 Playwright 通过。新增用例覆盖 1440px 和 1180px 下的原生形状拖放事件与延迟检查，验证 12 项进度留在框内且可用 Tab 聚焦、End 滚动。原有清单文本截断及经典滚动条用例继续通过。

Web 生产构建和 Tauri Release 已重建。`tools/release/assemble.ps1` 从已验证的标准包复用冻结 Worker 和模型，重新组装后全量校验 6,562 项，清单中只有桌面 EXE 哈希变化。EXE SHA-256 为 `6373f76bf25b73339837d19eb98dde5094cd8c3ab270f6e06242a942f473dbea`，发布清单 SHA-256 为 `e5491e13ce704798cc395e9140509f810a0b1a1bb2a1e28e795e79e6a4bb3c1a`。

在 1600×1000 窗口、96 DPI 的隔离配置下，从资源管理器分别拖放单个 WAV 和含 2,400 个合法 WAV 的目录。旧 EXE 在检查中把虚线框从 695×360 缩到 695×276 像素。新版的空闲、悬停、检查中和完成四态均为 695×360 像素，框顶始终距来源卡顶部 92 像素，来源卡与剪贴板入口的相对坐标和尺寸也一致。左右面板底边相差 42→0 像素。原生 UI Automation 整数像素测量的按钮高度为 61→103。确认对话框可打开、取消，Worker 完成 Desktop IPC v1 握手并持续就绪，窗口关闭后进程树回收。烟测只导入媒体并验证界面交互。
