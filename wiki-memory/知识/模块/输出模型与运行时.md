# 输出、模型与运行时

- Host 退出在后台等待 Worker，关机命令与正常回收共用退出预算；Windows 超时只发进程组终止请求，不无界等待驱动回收。Job Object 维护 Worker／后代归属，但不能修复显卡内核回调卡死。Windows 的退出码可能早于进程 HANDLE 变为 signaled，真实退出验收必须检查 HANDLE 和残留，不能只断言返回码 0。现场证据和待复验范围见 [[日志/2026-11-02-退出卡顿内核诊断与Host回收修复]]。

- `overwrite` 只接受磁盘旧文件；批内其他媒体及排队／运行任务预留使用既有 `task.conflict` 拒绝，不进入覆盖确认。检查 TXT／Markdown／SRT 和副本，采用既有归一化与大小写规则；同一计划内目标先合法去重。自动重命名同时避开旧文件和预留且各格式共享后缀，skip 记录跳过媒体但不计为本次新输出。规划失败不留下预留，完成／失败／取消继续释放。

- `paths.py` 统一解析安装、便携、用户模型目录和环境变量，不从源码层级猜项目根目录。
- 模型查找优先考虑便携目录 `models/huggingface`、`WHISPER_SUBTITLE_MODEL_DIR`、`HF_HOME` 和用户缓存。
- `output_store.py` 规划 TXT、Markdown、SRT 的原子写入、冲突检查、覆盖/跳过和自定义目录。
- 桌面新策略 `source` 将启用格式直接写入各媒体目录；`folders` 将 TXT／MD 合并放入 Text、SRT 放入 SRT，只创建启用格式需要的目录；`custom` 直接写用户选择的同一根目录，不额外创建格式文件夹或副本。目录输入先展开，再为每个媒体独立规划，继续沿用同名冲突与原子写入规则。
- IPC v1 schema、Rust Host、Python validator 同步接收新增 `source`／`folders`。旧 `compatibility` 和独立副本字段继续服务历史草稿，CLI 的旧路径不变；新策略不能提交给旧冻结 Worker。
- 新工作区默认 `source`；旧工作区配置的 `compatibility` 迁移为 `folders`，当前偏好禁用额外副本，历史任务草稿不改写。选自定义仅在系统对话框成功返回目录时提交路径；取消或失败保留原选择。
- Whisper CUDA 能力由 CTranslate2 判断，Qwen 由 PyTorch 判断；NVML 仍提供监控元数据。模型文件与共享依赖统一由注册表驱动，详见 [[决策/ADR-006-多后端本地识别与Qwen适配]]。
- 发布目录中的 Worker、模型快照和桌面 EXE 必须来自同一发布构建；开发验收入口是 target 下的 Release EXE。
