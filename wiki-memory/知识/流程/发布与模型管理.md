# 发布与模型管理

- `tools/release/build.ps1` 构建冻结 Worker、便携目录、manifest、SHA-256 和 SBOM；默认不生成 ZIP，分发时运行 `release:archive`，构建时需要 ZIP 则传 `-IncludeArchive`。`corepack pnpm release:build` 是默认便携版入口，仓库根目录 `buildStart.cmd` 可双击运行同一流程，构建当前本地源码并显示结果；它不自动拉取远程提交。NSIS 只由 `release:build:installer` 或显式传入 `-IncludeInstaller` 生成。
- `buildStart.cmd -CheckOnly` 仅检查现有 Python、模型结构、Node/Corepack 和 Cargo 是否可发现；不编译、不下载、不清空构建目录。Python 依次使用显式 `-BootstrapPython`、活动 `VIRTUAL_ENV`、工程已有 `whisper_env`／`.venv`／`venv`／`env`、PATH Python 和 `py -3`，要求 Windows x64 Python 3.10+ 及 venv/ensurepip。显式错误路径直接报错，不静默回退。模型依次来自 `-ModelDir`、`WHISPER_SUBTITLE_MODEL_DIR`、工程 `models/huggingface`。开发环境名称不再是硬依赖；预检与组装共用 Cargo 查找。
- 不同开发机器只同步 Git 源码，不会带入被忽略的环境、模型、`dist` 或 Rust 缓存。仅做 Web 预览可用 `runStart.cmd`，不要求该机器构建便携版；产物存在性必须在实际构建环境核验。预检通过仅表示本地入口条件通过，不能替代依赖安装、MSVC 编译或 EXE／模型验收。
- 发布运行时不依赖 Python、Node.js 或 Rust；Worker、CUDA 用户态依赖、WebView2 要按发布布局验证。
- 模型使用 `_internal/models/` 的直接离线快照，包含 Turbo 和本地可用的 Qwen／共享对齐模型；发布脚本负责版本一致性和产物清单。
- 正式交付只认完整 `dist/WhisperSubtitle/` 或按需生成的 `dist/WhisperSubtitle.zip`；技术依赖进入 `_internal/`。`target/release` EXE 只用于开发编译，不是完整交付物。
- 可选安装介质隔离在 `dist/installer/`，setup 必须与完整 `_internal/` 相邻；模型位于 `_internal/models`，微软签名的 WebView2 x64 离线安装器位于 `_internal/distribution`。bundler 不下载前置依赖。

2026-09-26 最新完整便携版已通过 `buildStart.cmd` 纳入当前本地源码，包括 9 月 24–25 日的文件输出和启动区整改；完整清单、ZIP／校验和、冻结 Worker 协议与正式 EXE 生命周期验收通过。同日四预设旁白校准后再次全量重建；当前识别行为以 [[日志/2026-09-26-校准四预设并修复配乐旁白漏识别]] 的真实 Turbo、固定夹具和冻结 Worker 验证为准，旧 CUDA／CPU 记录仅用于追溯。不能混用旧冻结 Worker 与新前端／Host。便携版中文说明源为 `tools/release/user_guide.zh-CN.md`，应在 assemble 之前更新，不能仅修改已生成 dist 内的副本。

只有显式 `-KeepBuild` 保留了完整冻结 Worker、构建环境和 stage，且它们仍与源码匹配时，才可直接运行 `tools/release/assemble.ps1`；它仍重新构建 Web／Tauri，再整体生成便携目录、manifest 和 SHA256，ZIP 需 `-IncludeArchive`。成功发布默认删除中间态，不能假设上轮 stage 仍存在。2026-09-20 的错误文案修复曾按复用 stage 流程重新组装并完整复验；任何类似更新都不能只替换成品 EXE。
